# Proposal

## Why

Подготовленные приложения уже имеют версии, оформление, независимые назначения, перечень и историю ZIP, но пока нельзя выпустить согласованный PDF-том и безопасно изменить занятые номера во всех представлениях. Следующий законченный результат — одна подача с переносимым профилем, проверенной перенумерацией и отдельными файлами/томами с точными страницами и переходами.

Объём **принят пользователем 13 ноября 2026** в составе [плана 0.7.0](../../../docs/RELEASE-PLAN-TO-1.0.md), N03–N08; проверки/перенос/ресурсы — N38–N42 в относящейся части. Повторного согласования этого объёма не требуется. Это подготовка 0.7.0, не разрешение на публикацию.

## What Changes

- Необязательные PDF-тома: готовые материалы, опциональный основной документ, перечень, разделители, общие страницы, закладки, внутренние и межтомовые переходы.
- Версионированная карта исходная часть/страница/область → подготовленная страница → том/страница; явные назначения точной страницы для управляемых ссылок.
- Preview состава/порядка/страниц/разбиения, ограничение размера/страниц, прогресс/отмена/атомарная публикация и неизменяемый снимок в нынешней истории ZIP.
- Именованные версионированные профили оформления/ссылок/имён с переносом JSON и preview применения, без стирания местных исключений.
- Preview смены уже назначенных номеров/обмена/путей; согласование управляемых упоминаний DOCX и явно выбранных ручных диапазонов без глобальной замены текста. Панель использует нынешнее явное обновление Word.
- Самодостаточный архив подачи включает выбранный профиль, настройки/карту томов, происхождение производного DOCX и историю результатов; старые проекты продолжают открываться.

Не входят: импорт дерева папок/предложения пар/OCR/полнотекстовый поиск (0.8), сервер/синхронизация/совместная работа/AI, переустановка неизменённой панели. Обычный ZIP, отдельный перечень и автономная работа без Word/библиотеки/переводчика сохраняются. Конвертер нужен только для включённого основного DOCX. Подписанный ready PDF остаётся отдельным побайтовым исходником; подпись не объявляется подписью пересобранного тома. Поля/аннотации не исчезают молча; невозможность сохранить элемент блокирует конкретный том с объяснением.

## Capabilities

### New Capabilities

- `submission-volumes`: настройки/карта/компоновка/пагинация/навигация/снимки одного или нескольких PDF-томов.
- `submission-profiles`: неизменяемые версии переносимых именованных профилей и явное применение к подаче.

### Modified Capabilities

- `project-workflow`: preview и согласованная смена существующих назначений без изменения исходников/других подач.
- `citation-linking`: безопасное обновление известных диапазонов производного DOCX и явные нерешённые случаи.
- `portable-export`: необязательные тома и проверенные относительные/внутренние цели вместе с обычными файлами.
- `export-history`: снимок/контроль целостности томов, карты/профиля/назначений и устаревание.
- `project-backup`: перенос новых настроек/применённого профиля/происхождения DOCX без внешнего каталога профилей.

## Impact

Python/FastAPI и React; переиспользуются Store, batch, index_documents, история/backup, pypdf/reportlab, библиотечные версии и Word updatePlan/applyUpdates. Новые действия имеют локальный доступ/пределы ресурсов. Пакеты Windows x64/Mac Intel/Mac ARM, обмен архивами, искусственные нагрузки и новый UI проверяются отдельно от настоящего Word/просмотрщиков. GitHub Release и merge только по указанию пользователя.
