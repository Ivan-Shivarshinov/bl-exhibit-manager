# Design

## Context

Принятый объём и источники — proposal.md и план N03–N08. Store хранит неизменяемые inputs, batch уже проверяет preview/token/коллизии и сохраняет проект атомарно; index/history/backup и Word update уже реализованы. Эти механизмы расширяются. Локальный/серверный rewrite и OCR не нужны.

## Goals / Non-Goals

**Goals:** самодостаточная карта производных/томов; воспроизводимый preview; переносимый профиль; согласованная перенумерация и проверенные выходные файлы. **Non-Goals:** распределённая транзакция живого Word и проекта, повторный onboarding, расширение до 0.8.

## Decisions

1. **Формат проекта 4.** Новые поля volume_settings, applied_profile и журнал assignment_operations; upgrade создаёт нынешний backup до записи, старые схемы читаются без изменения до нового действия. Настройки строго валидируются также в restore. Выбранный профиль встроен целиком, общий каталог профилей не требуется для восстановления. Прежние ZIP сохраняются. Изменённый DOCX — новый content-addressed input с цепочкой исходного main, не запись поверх него.
2. **Профили.** Отдельный каталог неизменяемых JSON-версий в корне данных, ограниченные поля/размер; импорт/экспорт JSON с идентичностью/хешем. Штампы, citation_style, правила имени/папки/обозначения, настройки тома. Применение через preview токен проекта+версии; местные overrides/ручные имена сохраняются по умолчанию, явный сброс отдельно. Изменение профиля не меняет уже применённые подачи.
3. **Назначения.** Новая операция поверх batch: таблица document_id→назначения, финальная проверка целого проекта допускает обмен номеров/путей, но не дубли. Исходный проект не мутирует до успеха. Производный DOCX переписывает только подтверждённые известные диапазоны: управляемые ссылки автоматически предложены; остальные строки выбираются явно, ручные/неподдержанные показываются как требующие решения. Сохраняются run-оформление/локаторы/другие ссылки. После изменения пересканировать производную и сохранить точные назначения. До записи создаётся архив, receipt связан с планом. Живой Word остаётся отдельным явным шагом updatePlan/applyUpdates; UI не выдаёт отсутствие подтверждения Word за успех.
4. **Карта страниц.** Для каждого документа: stable ID, revision/хеш подготовленного PDF, part/original hash, source_page/rect/occurrence, prepared_page, volume/local_page/global_number. Отдельная строка main. Порядок identifier/project/folder/явная таблица; перевод/выбор сохраняются. Цель конкретной ссылки выбирается по подготовленной странице с видимым источником, привязана к ревизии. Не угадывать параграф как PDF-страницу. Для включённого main создавать отдельную конверсионную копию с уникальными целями каждой управляемой ссылки, не заменяя обычный DOCX/PDF в ZIP.
5. **Компоновка.** pypdf/reportlab из текущих зависимостей; append с переносом outlines/destinations/полей, пространство имён полей по stable ID. Исходник ready сохраняется отдельно. Индекс всех материалов присутствует в каждом томе, указывает том/диапазон и кликабелен; разделители опциональны. Итерация числа страниц индекса до стабильности. Уменьшение лимитов монотонно разбивает по границам материалов; слишком большой одиночный материал/сам индекс — явный отказ без скрытого разрезания.
6. **Пагинация и ссылки.** По умолчанию номер в добавленной верхней полосе, не поверх содержания; выбранное наложение проверяется по фактически отрисованной области. Смешанные размеры/повороты сохраняются. Десятичный номер/шаблон подписи/начало/положение в настройках. Внутри тома — GoTo; между томами — относительный GoToR Filespec с Unicode, пробелами/# как именем файла, не URI. Закладки с отдельными ID, возврат к перечню. Не относящиеся к управляемым файлам внешние ссылки сохраняются. Неподдержанный элемент/непроверяемая цель блокирует сборку, не удаляется ради успеха.
7. **Задания/preview.** Ограниченное временное хранилище вне inputs, один снимок на проект; подготовка/сборка в фоне, статус/отмена и stale-проверка перед публикацией. Ограничения общего числа страниц/входных/выходных байтов и свободного места. Обычный ZIP содержит отдельные файлы, включённые тома и JSON-карту с суммами. Проверка всех ссылок/карты/страниц/байтов до history.save_export. Отмена/ошибка очищает только принадлежащие заданию временные файлы, не публикует частичный ZIP. Закрытие приложения делает незавершённое interrupted с возможностью повтора.
8. **Архив/история.** История фиксирует профиль/назначения/настройки/суммы томов и карты. Архив включает project JSON, все исходники/производный DOCX и старые результаты; временные файлы исключены. Независимое восстановление сохраняет происхождение и новые настройки, но не сессии. Старый клиент отказывается от схемы 4 без потери данных. Скачивание использует проверенный неизменяемый ZIP из истории; второй download ZIP не создаётся, поэтому закрытая вкладка не оставляет дубли. В памяти сохраняются только ограниченные квитанции.

## Risks / Trade-offs

- Формы/подписи/повороты → проверка canonical fields/виджетов/рисунков и rendering; исходная подпись относится только к отдельному исходнику, не к тому. Не поддержанный безопасно случай блокируется с именем/страницей. Верхние поля получают отдельные имена без искусственного родителя (проверка растров PDFium); вычисления/сценарии форм, XFA и портфолио отклоняются до выдачи. Контролируется число всех исходных аннотаций после переноса.
- Несколько томов/повторный индекс → монотонный расчёт и предел итераций; проверка физической страницы назначения, а не только её подписи.
- Неоднозначная перепись Word → отказ до записи и конкретная строка, без глобального replace. Проект и живой Word не общая транзакция.
- Рост диска → lifecycle собственных temporary, лимиты, ограниченное число QA-результатов. Готовые три пакета/суммы сохраняются, массовые дубликаты распаковок не создаются.
- Неизвестный viewer → автоматическая структура отдельно от реального перехода, точная матрица/оставшиеся ручные шаги. Запрет управления ПК сохраняется.

## Migration Plan

Схемы 1–3 читаются по прежним правилам. Новое действие делает backup и upgrade до 4, только затем сохраняет настройки/результат. Ошибка миграции не меняет проект. Проверить восстановление 0.6.0→0.7.0 и охраняемый отказ старого клиента; откат через сохранённый архив, не стирание новых полей. Нативные пакеты/CI относятся к одному коду, релиз не публикуется.
