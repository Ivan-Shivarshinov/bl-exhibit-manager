## Why

При новой редакции DOCX пользователь не должен заново сопоставлять однозначно сохранившиеся ссылки; прежний собранный комплект должен оставаться воспроизводимым. Это перенос ранее согласованных шагов 4–5 в OpenSpec, а не предложение нового объёма.

## What Changes

- Переносить подтверждённые связи и ручные границы при однозначном соответствии редакций, показывать добавленные/изменённые/удалённые упоминания.
- Не угадывать решение для неоднозначных повторений.
- Хранить каждую успешную сборку как неизменяемый ZIP с составом и сравнением.
- Работать при обычной загрузке DOCX без панели Word.
- Реализация объединена с исключениями/готовыми PDF/папками rc.5, проверена и выпущена в v0.2.0.
- Не входят: полноценный diff текста Word, библиотека дела, совместное редактирование и перенос целого проекта между компьютерами.

## Capabilities

### New Capabilities
- `submission-revisions`: перенос сопоставлений между редакциями основного документа.
- `export-history`: неизменяемые версии готовых комплектов.

### Modified Capabilities
Нет.

## Impact

`exhibit/revisions.py`, `history.py`, `project.py`, API и `web/src/WordWorkflow.jsx`. Дополнительное локальное место для ZIP. Пользователь должен различать историю выдаваемых комплектов и резервную копию редактируемого проекта.
