## 1. Каталог и версии

- [ ] 1.1 После первых двух этапов реализовать отдельное локальное хранение библиотек/материалов/версий с атомарной публикацией и проверкой состава; существующие проекты не требуют библиотеки.
- [ ] 1.2 Реализовать явное сохранение материала из подачи: оригинал, подтверждённый перевод, настройки и при наличии подготовленный PDF; не переносить чужие сопоставления основного DOCX.
- [ ] 1.3 Реализовать новую неизменяемую версию и сравнение состава по хешам/реквизитам; прежние версии сохраняются.

## 2. Повторное использование

- [ ] 2.1 Реализовать предварительный импорт выбранной версии в подачу: независимые копии файлов, новый ID документа и происхождение; проверить конфликты номера/имени/папки до записи.
- [ ] 2.2 Реализовать два явных варианта — оригинал с переводом для оформления и готовый PDF без обработки; показать прежнее обозначение готового PDF и пересчитать подтверждение при изменении оформления.
- [ ] 2.3 Реализовать обнаружение более новой версии и её явное применение к выбранному приложению с сохранением местных назначений; затронутые оформление/ссылки требуют проверки, старые ZIP неизменны.

## 3. Интерфейс и сохранность

- [ ] 3.1 Добавить необязательный каталог дела, поиск по реквизитам, выбор версии, просмотр состава/различий и импорт в подачу.
- [ ] 3.2 Расширить архивирование отдельным типом библиотеки с версиями; проверить конфликт восстановления и отсутствие зависимости архива подачи от библиотеки.
- [ ] 3.3 Применить защиту обновлений схемы для новых метаданных; старые проекты и прежние архивы открываются без назначения библиотеки.

## 4. Проверка и выпуск

- [ ] 4.1 Пройти полный сценарий двух подач с разными номерами одного материала, новой версией перевода и явным обновлением только одной подачи; сравнить исходники и прежние ZIP.
- [ ] 4.2 Проверить недоступную библиотеку, повреждённый материал, конфликт назначения, сбой импорта и повторное открытие; неполный импорт не публикуется.
- [ ] 4.3 Проверить перенос архива подачи и библиотеки между нативными пакетами Windows/Mac; повторное использование не запускает новый перевод и не требует панели.
- [ ] 4.4 Обновить инструкции/OpenSpec/WORKSTATE, выполнить строгую валидацию и подготовить выпуск. Зафиксировать фактическую матрицу проверок; замечания коллег после отправки релиза обрабатываются отдельно.

Третий этап. Критерий готовности — независимое повторное использование, а не общая синхронизация подач. Отсутствие обратной связи не подтверждает неизвестные сценарии и не задерживает следующую работу.
