Обновлено 9 октября 2026. Ветка `codex/case-material-library` начата от принятого плана `fc62480`. Это доказательства реализации, не объявление выпуска. Публикация GitHub Release не разрешена.

## Выполненные срезы

- `tests/test_library.py`, `test_library_api.py`, `test_library_versions.py`, `test_library_backup.py`, `test_library_bulk.py`: валидные/повреждённые схемы; атомарность и сбои до/после копирования; отмена, устаревший выбор и идемпотентность; роли, привязка перевода и исключение черновика; собственные номера/файлы; обновление только B и возврат v1; конфликты местного названия/выборки/перевода, диапазон за новыми страницами; проверенные снимки при ошибке записи; два типа архива, конфликт/копия, недопустимые ZIP; 100 PDF, исключение ошибок, дубликаты, фильтры, справка локальных подач, скрытие без изменения файлов.
- Полная проверка исходников Windows: 270 Python-тестов и 23 JS-теста прошли. Изменение выборки теперь снимает подтверждение применимости перевода: прежний тест обновлён с проверкой отказа до повторного подтверждения.
- Edge 154, Windows 11, интерфейс из исходников: сохранение оригинала и подтверждённого перевода → другая подача/Annex 12 → подтверждение оформления → ZIP. Хеши исходной подачи неизменны. Просмотр и отсутствие переполнения/JS-ошибок — 1440/760/390.
- Там же: публикация v2 с новым переводом, сравнение на широком/узком экране, явное обновление B с сохранением ID/Annex 12; скачивание архива и восстановление независимой копии библиотеки. Это проверка браузерного интерфейса, не Word.
- `scripts/library_ui.cjs`: старый путь готовый PDF → ZIP без библиотеки; загрузка 100 различных искусственных PDF, общая роль, публикация, импорт трёх, «где используется», скрытие/возврат, комбинация реквизитов/меток в фильтрах, переход к приложению из справки, два местных конфликта с одним повторным сравнением, Escape и возврат фокуса. Реакция интерфейса на загрузку — 34,7 мс; JS-ошибок и переполнения на трёх размерах нет.
- `scripts/verify_library.py` / `library_checks.py`: две библиотеки/две подачи/20 материалов, Annex 3 и Annex 12, обновление только B/возврат v1, неизменность A/исходников/старых ZIP, экспорт без библиотеки. Переводы берутся из искусственных PDF; команды перевода не запускаются.
- `scripts/generate_legacy_archives.py` создаёт искусственные архивы **кодом опубликованных тегов v0.3.0 и v0.4.0**; восстановление и экспорт в новых исходниках прошли, исходные файлы и история совпали побайтово, schema 1 не переписывается при открытии.

- Архив проверяет фактические страницы/размеры PDF, а не только SHA-256. Манифесты читаются/переносятся по одному, PDF потоками; коллекция содержит идентификаторы и компактные контрольные суммы. Проверены поддельные сведения о страницах с валидной контрольной суммой, лимиты записей/размера, отмена и повтор восстановления копии.
- Настоящий Microsoft Word, Windows 11: `scripts/verify_library_office.py` прошёл преобразование DOCX и проверку относительных ссылок DOCX/PDF после импорта Annex 3/12 и переименования только B. Исходные байты/текст/оформление DOCX и прежние ZIP неизменны; Word-каталог отдаёт названия выбранной подачи. Это реальная конвертация Word; взаимодействие с панелью Office.js ей не приписывается. Office.js не менялся.

## Большой архив

Отдельная проверка Windows 11: сохранены и восстановлены 1100 материалов/3100 версий (нагрузочный каталог плюс набор 100 PDF), затем проверена каждая версия и её части. 3202 файла, 6,66 МБ распакованных данных. Во время проверки с tracemalloc пик выделений Python — 14,9 МБ; память нативных библиотек этим измерением не охвачена. Полный инструментированный проход занял 75,7 с; это не бюджет скорости архива. Служебный статус сохраняется с частотой до 10 раз/с, а завершение/отмена — сразу, чтобы каждое сообщение о файле не требовало синхронной записи на диск. При сохранении используется один защищённый снимок каталога; манифесты обрабатываются по одному. Нативный нагрузочный сценарий дополнен архивированием и восстановлением всех 3100 версий.
