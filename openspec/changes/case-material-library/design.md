## Context

Сейчас каждая подача содержит собственные документы и переводы; история сохраняет только готовые комплекты. Библиотеки нет. После первого этапа доступен проверяемый архив и защита изменений схемы. Мотивация — proposal.md.

## Goals / Non-Goals

**Goals:** повторное использование без скрытых общих изменений и без обязательного нового уровня организации.

**Non-Goals:** сервер совместной работы, глобальная дедупликация всех проектов и автоматическая синхронизация ссылок между подачами.

## Decisions

- Библиотеки хранить отдельно от существующих каталогов подач. Материал имеет постоянный ID, версия — отдельный ID, состав и хеши файлов. Версию после публикации не редактировать; сохранение обновления создаёт следующую.
- Начать с файловой модели и атомарной публикации, уже применённой для истории. Новая СУБД не нужна для первого каталога и явного выбора версии. Индекс для поиска по названиям/обозначениям можно восстанавливать из метаданных.
- Импорт копирует файлы и назначает новый ID документа в целевой подаче. Происхождение хранить отдельно: библиотека/материал/версия. Отказ от общей изменяемой ссылки означает больше места на диске, зато архив подачи полностью автономен.
- В библиотеку переносить оригинал, подтверждённый перевод, настройки выбора/оформления и при наличии подготовленный PDF; не переносить чужие сопоставления с основным DOCX. Незавершённый черновик остаётся в проекте и его резервной копии; не выдавать его за повторно используемый проверенный перевод.
- Разделить импорт оригинала с переводом для нового оформления и импорт готового PDF без обработки. Для второго показать исходное обозначение в результате. Для первого заново вычислить готовность после применения номера/папки и требовать проверки изменённого результата. При совпадающих проверяемых параметрах перевод повторно не генерировать.
- Обновление версии показывает состав изменений и применяется к выбранному документу, сохраняя местные номер/папку/имя. Новое содержимое требует подтверждения результата; конфликт назначений проверять до записи. Устаревшую версию можно продолжать использовать.
- Библиотека получает отдельный тип архива на основе механизма первого этапа. Архив отдельной подачи включает её собственные копии материалов; автоматически включать все материалы дела нельзя. Не добавлять удаление используемых версий в первый выпуск.

## Risks / Trade-offs

- Смешение библиотечного материала и номера приложения → номер относится к подаче, исходное обозначение готового PDF показывается как свойство сохранённого результата.
- Замена перевода меняет комплект → явное обновление, сброс только затронутых подтверждений и неизменность прошлых ZIP.
- Большие библиотеки расходуют диск → показывать размеры и состав, потоковая работа; дедупликация между проектами отложена.

## Migration Plan

Старые проекты не требуют библиотеки и продолжают открываться. Добавить происхождение как необязательные метаданные через правила безопасного обновления. Проверить две подачи с одним материалом, новую версию перевода, отключение библиотеки и перенос архива; затем выпустить пакет для обычного сбора обратной связи.
