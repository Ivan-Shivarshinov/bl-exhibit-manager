# Design

## Context

Подача хранит исходники по SHA-256, библиотека хранит неизменяемые версии, PDFium уже показывает страницы. Приложение выдаёт переносимый ZIP, а архив проекта проверяет список допустимых файлов отдельно от экспорта.

## Goals / Non-Goals

- Сделать навигацию к месту в материале общей для текста PDF и OCR. Работа остаётся локальной на Windows и macOS.
- Сохранить независимость старого экспорта, обычного открытия и метаданных каталога от поисковых операций и движка.
- Подготовить переносимые данные без привязки к программам и абсолютным путям на компьютере.

## Decisions

1. **Источник и координаты.** Единица распознавания — страница исходного PDF с SHA-256 содержимого. Для навигации используются нормированные координаты относительно видимой страницы, с учётом поворота. Итоговая область для ручной правки соответствует исходной строке. Подготовленные фрагменты используют отдельную область поиска. При смене исходника результаты старой версии перестают участвовать в поиске по текущей версии.
2. **OCR.** Первый адаптер запускает локальный Tesseract через список аргументов и передаёт ограниченное изображение страницы через stdin. TSV даёт строки, координаты и уверенность. Определяются доступные языки `eng`/`rus`, отсутствующие языки явно показаны. Tesseract требуется только для нового распознавания. Приложение не загружает движок или модели само. Для выпуска проверяется установка каждой поддержанной платформы. Встраивание нативных библиотек оставлено для отдельной оценки поставки. [Документация Tesseract](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html).
3. **Сохранение.** OCR и сверенный текст хранятся в отдельных атомарных записях страницы с ревизией. Прежняя ручная правка не вытесняется поздним результатом. Перед записью повторно проверяется SHA-256 текущего исходника. Архив включает проверяемые записи страниц, но не вычислимый поисковый кэш. Существующие проекты открываются в прежней схеме. Первое сохранение OCR повышает схему через обычный проверяемый резервный архив.
4. **Поиск.** Первый проход по исходным PDF использует координаты PDFium и сохранённые строки OCR. Скан, пропущенная страница и прерванная выдача явно отмечаются. Последующее индексирование переиспользует хеши источников, а фильтры выбирают доступные версии до запроса. DOCX использует абзац или сноску. История и скрытые версии включаются по отдельному выбору.
5. **Импорт и производные.** Относительные пути используются как данные, сохраняемые только после проверки. Существующий предпросмотр библиотеки и решения о дубликатах остаются точкой применения. Предложение пары создаётся лишь для однозначной раскладки или имени, решение подтверждает пользователь. Производная PDF создаётся как новый файл, с указанием исходника и операции. Для слоёв, форм и подписей нужна отдельная проверка поддержки конкретного преобразования.
6. **Первая поисковая копия.** Невидимый текст накладывается на страницы с подтверждённым OCR. Если скан не проверен, PDF содержит форму или подпись либо преобразование целевой геометрии не проверено, копия отклоняется и объясняет причину. Копия зафиксирована хешем источника и хешем проверенного текста. Оригинал, история и версия в библиотеке сохраняются.
7. **Области расширенного поиска.** Подача предлагает исходники, подготовленные страницы или основной DOCX. Для фрагмента используются только целиком включённые символы PDF и строки OCR. Переход открывает сам фрагмент. Цель в томе выдаётся только для актуальной карты с тем же хешем источника и номером подготовленной страницы. Библиотека ищет по текущим видимым версиям. Старые и скрытые включаются отдельными переключателями. Переход открывает именно найденную версию. При сохранении PDF из подачи новая версия материала получает подтверждённый OCR по совпадающему хешу, который переносится с архивом библиотеки. DOCX показывает совпадение в исходном абзаце или сноске.
8. **Индекс и очередь.** Вычислимый текст PDF хранится в ограниченном локальном SQLite-кэше по хешу и странице. Поиск использует кэш для фильтрации, а координаты совпадений проверяет по исходнику. Ручная индексация и OCR диапазона используют существующие отменяемые операции. После завершения страницы данные уже доступны; при остановке операция отмечается прерванной, а повтор переиспользует завершённые страницы.
9. **Структурные копии.** Поворот меняет ориентацию выбранных листов в отдельной копии всего документа. Объединение принимает явно упорядоченные PDF и диапазоны, разделение требует указать каждую страницу ровно один раз. Каждая производная содержит SHA-256 исходников и карту страниц. Для операций с удалением или переносом листов блокируются неподдержанные структуры и переходы, чью цель нельзя гарантировать. Внешние ссылки с абсолютным URL сохраняются.

## Risks / Trade-offs

- Повреждённая страница или зависший движок → ограничение размера растра и времени, ошибка конкретной страницы, пригодность остальных результатов.
- Поиск по плохому OCR → видимое состояние полноты, оценка уверенности, правки со сравнением с изображением и подтверждение для перевода.
- Изменение данных во время чтения → проверка актуального источника при записи и предъявлении результатов. Дорогие обработки выполняются без глобальной блокировки проекта.

## Migration Plan

Проверять старые проекты и архивы на текущих платформах. До первой durable-записи OCR создать прежний архив. Для возврата к 0.7 использовать этот архив. Поисковый кэш пересоздаётся после переноса, сохранённый OCR читается без OCR-движка.
