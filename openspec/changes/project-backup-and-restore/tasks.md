## Доказательства завершения

Реализация завершена 24 сентября 2026 в `codex/project-backup-and-restore`, PR #4. Исходники пакетов 0.3.0 — `768d8bf`. Создан черновик GitHub Release с тремя приложениями и тремя SHA-256; публикации не было. Основные требования синхронизированы в `openspec/specs/project-backup/` и `project-schema-upgrades/`.

- Финальный CI `35994695642`: 186 Python-тестов (20 специализированных сценариев архива), 11 JavaScript-тестов, нативная сборка/запуск/перенос всех трёх пакетов. Windows x64, Mac Intel, Mac Apple Silicon восстановили архивы каждой из трёх платформ с побайтовой проверкой исходников, черновиков и истории.
- Настоящий Microsoft Word Windows локально и LibreOffice на обеих архитектурах Mac: архив → отдельное хранилище → новая редакция DOCX → новый ZIP. Сохранены ручные решения, прежние ZIP и относительные цели DOCX/PDF. Панель, сертификат и авторизация переводчика не нужны для восстановления.
- Chromium/Playwright Windows, HTTP 8791→8793, 1440×1000 и 900×900: сохранение/скачивание, предварительная проверка, восстановление, конфликт/отмена, повреждённый архив, новая редакция и новый ZIP. Скриншоты проверены; ошибок приложения нет. Единственный 400 — ожидаемый отказ повреждённому архиву. Browser plugin отсутствовал; использован установленный Playwright.
- Нагрузка на финальном коде: 537 061 956 байт, две большие версии истории, сохранение 18,08 с, восстановление 9,48 с, пиковые выделения Python 4,13 МиБ (tracemalloc, не память всего процесса). Байты не изменены.
- Сбои записи/переименования, активный перевод, одновременная запись, неизвестные версии, неполные metadata, превышение ограничений, дубли и небезопасные записи ZIP покрыты тестами. Схема 1 не мигрирует; искусственное преобразование 1→2 проверяет предварительную копию и откат при ошибке.

Ограничение доказательств: новая перепривязка копии в живом Office.js отдельно не проверена. Импорт, план обновления и изоляция точных маркеров покрыты Python/JavaScript; прежняя ручная проверка панели пользователем сохраняет свой статус. Новую проверку можно выполнить при обычном тестировании релиза: восстановить копию проекта, открыть копию исходного DOCX в Word, выбрать восстановленный проект в панели, проверить ссылки и применить обновления. Изменения должны относиться к копии, исходный проект и прежние ZIP остаются прежними. Ожидание формального ответа коллег не требуется.
