## Context

Store хранит `project.json` со схемой 1, неизменяемые `inputs`, состояния `translation-*.json` и `exports/<id>/`. Запись JSON уже атомарная; история ZIP имеет собственные контрольные суммы. В Word-ссылки встроены ID проекта и документа. Мотивация — proposal.md.

## Goals / Non-Goals

**Goals:** один переносимый архив проекта, проверка до записи и безопасное продолжение работы. Использовать существующую файловую модель и локальный сервер.

**Non-Goals:** новая СУБД, универсальная система миграций, фоновые облачные копии и импорт настроек компьютера.

## Decisions

- ZIP с отдельной версией архива и манифестом размера/хеша каждого файла. Версия архива не равна версии приложения или проекта. В отличие от простого копирования каталога, манифест задаёт полный проверяемый состав.
- Состав задаётся разрешёнными категориями: проект, все сохранённые исходники, черновики/разметка перевода, подтверждённые PDF и завершённая история. Временные файлы и воспроизводимые кэши не обязательны; неизвестные значимые категории требуют явного расширения формата, а не молчаливой потери. Не обходить весь корень пользовательских данных.
- Снимок фиксировать под блокировкой записи проекта; активный перевод этого проекта должен завершиться либо быть явно остановлен пользователем. Долгая передача готового архива не держит блокировку. Не останавливать сторонние процессы автоматически.
- Проверять записи ZIP до извлечения, нормализованные пути с учётом регистронезависимых файловых систем, длины, количество и суммарный распакованный размер. Потоковая запись во временный каталог рядом с данными, финальная проверка и атомарное переименование. Без произвольного `extractall` и исполнения содержимого архива.
- В обычном переносе сохранять ID. При конфликте — только явная копия с новым ID; стабильные ID документов внутри копии можно сохранить. Для исходного DOCX хранить привязку прежних управляемых маркеров к копии в метаданных конкретного проекта/источника. Новые и обновлённые ссылки получают новый ID проекта; исходник и старые ZIP не переписываются. Не вводить глобальный псевдоним, который перенаправил бы ссылки другого проекта. В панели для копии нужен выбор восстановленного проекта и проверка ссылок.
- Обновления схемы оформлять последовательными преобразованиями с предварительной копией, проверкой результата и отказом на неизвестной версии. Сейчас схема 1 — исходная точка; не повышать её только ради наличия механизма. Возврат — восстановление копии совместимой версией приложения, не обещание обратной миграции.

## Risks / Trade-offs

- История может быть большой → потоковый архив, оценка свободного места, понятный отказ; не сокращать историю молча.
- Старые управляемые Word-ссылки ведут в прежний проект → тест копии при одновременном наличии оригинала, отдельная проверка импорта и панели, никакой глобальной подмены ID.
- Внешние конвертеры дают разные новые PDF → сравнивать байты исходников/старых ZIP, а для новой сборки состав, ссылки и оформление, не требовать идентичных байтов заново сконвертированного PDF.

## Migration Plan

Сначала зафиксировать формат и чтение проектов v0.2.0; затем экспорт, проверку/восстановление, UI и защита обновлений. Автоматически прогнать архив Windows→Mac и Mac→Windows через нативные пакеты на искусственных проектах. Выпуск передаётся пользователем коллегам; отсутствие отзыва не считается тестом и не блокирует следующую работу.
