## Адресные исправления при проверке

- Номер при наложении мог оказаться вне правого края: теперь место рассчитывается для номера и возврата вместе, проверяется весь прямоугольник, regression проверяет реальные координаты символов.
- Добавление искусственного родителя к полям приводило к исчезновению их изображения в PDFium. Теперь существующие верхние поля получают отдельные имена без нового родителя. Поля с одинаковыми исходными именами независимы; для 0/90/180/270° изображение исходной части с полем побайтово совпадает с растром в томе.
- Старые backup fixtures содержали произвольные байты вместо ZIP. Они заменены настоящими искусственными ZIP без ослабления проверки истории.
- Windows CI воспроизвёл одинаковое время двух быстрых экспортов: старый комплект мог оказаться первым в истории. Новые записи получают строго возрастающее время в пределах подачи, в том числе при одинаковом такте часов; regression фиксирует часы без искусственной задержки.
- Нативная Office-проверка выявила отказ сохранения обычного перечня после обновления проекта до схемы 4. Настройки перечня теперь повышают формат до минимально нужного, сохраняя уже более новый; frozen API проверяет индекс после перенумерации и вместе с томами.
- На пределе 2000 записей истории назначений операция отклоняется до записи. Проверка подтверждает, что проект остаётся читаемым, исходники и прежний ZIP не меняются; итоговая запись проходит строгую проверку метаданных перед сохранением.

- Закрытие вкладки до скачивания могло оставить второй временный ZIP. Скачивание теперь идёт прямо из проверенного файла истории; повторные невостребованные результаты не создают download-копий, закрытие сервиса сохраняет историю.

## Предварительно объявленная нагрузка

`scripts/volume_stress.py`: отдельный процесс для каждого профиля, предел RSS 2,5 ГБ; время — 30/180/600 секунд. Готовые большие PDF не записываются на диск. Локально Windows: 6 страниц/3 материала — 0,125 с и 58 МиБ; 500/50 — 3,985 с и 165 МиБ; 10 000/1 000 — 104,078 с и 711 МиБ, 20 томов, 330 315 452 байта результата. Это искусственная нагрузка, не гарантия времени для любого PDF/компьютера. Нативные измерения фиксируются отдельными JSON.

Программные предохранители: 2 000 материалов, 512 МБ входных подготовленных PDF, 10 000 исходных и 20 000 итоговых страниц, 100 томов, 1 ГБ PDF-результата. Проверяются отмена, устаревание, слишком большой одиночный материал, ошибка записи и восстановление после остановки. Единственный материал не разрезается автоматически.

Локально на Windows: общий набор 391 Python (1 skip) / 34 JS, Vite и строгая OpenSpec — успешно. Chromium также проверяет собственный порядок, интерактивный переход между томами/возврат, отмену 1000 страниц без истории и повтор.

Полный сервис отдельно измерен на 500 страницах/50 материалах: 8,797 с с загрузкой, ZIP и историей; 233 476 096 байт RSS, 16 752 438 байт снимка, 25 220 051 байт всей тестовой папки, ZIP 3 658 482 байта. Заданы бюджеты до старта: 180 с / 1,5 ГБ RSS / 150 МБ диска. Папка после проверки удалена, исходники и прежний ZIP совпали. Это полный сервис на Windows, не проверка максимума через GUI.

Принудительно остановлен собственный отдельный процесс во время сборки 1000 страниц: после запуска состояние interrupted, собственная временная папка очищена, project.json/исходник/прежний ZIP совпали; пользовательский рабочий стол не управлялся.

## Границы оставшихся ручных проверок

Настоящий Word 0.7.0 не управлялся. Для опциональной панели остаётся один новый сценарий: в искусственной подаче с двумя уже вставленными управляемыми сносками обменять номера в приложении; в открытом Word выполнить прежнюю команду проверки/обновления ссылок. Ожидается: ID/порядок материалов и локаторы сохраняются, меняются только согласованные обозначения; ручная правка показывается как конфликт. Повторная установка панели не требуется. Это проверка дополнительной интеграции, не обычной загрузки DOCX и сборки томов.

Внешние PDF-просмотрщики на Mac этим CI не подтверждены. Если используется конкретный просмотрщик, распаковать искусственный `output/qa-v070/office-arm/Submission.zip` целиком; открыть Volume 01, проверить перечень и первую сноску (Volume 03, физическая страница 4 / общий номер 11), возврат к перечню и повтор после переноса всей папки. Эти нажатия уже подтверждены в SumatraPDF 3.6.1 на Windows; повторять их на той же среде не требуется. Внутренний предпросмотр приложения проверяется Chromium на целевых ОС.
