# Оставшиеся выпуски до командной платформы 1.0

Редакция плана: 13 ноября 2026; результат 0.7.0 внесён 14 ноября. База опубликованного продукта — v0.6.0. План принят пользователем; кандидат 0.7.0 реализован и проверен в `codex/submission-pdf-volumes`, три пакета готовы, публикация не разрешена. [Результаты и ограничения](PDF-VOLUMES-VALIDATION.md). [Сверка требований и реализации](SCOPE-RECONCILIATION.md) хранит источники, существующие возможности B01–B18, остаток N01–N43 и решения A01–A08.

## Основание новой разбивки

Пользователь выбрал командную платформу к 1.0. Здесь заново распределён **только оставшийся объём**, а не весь перечень функций продукта. Уже работающие архивы, версии, массовые операции, настройка Word, хранение данных, обновление ссылок и продолжение одиночного перевода не становятся новыми задачами под другим названием.

Предыдущие редакции были предложениями исполнителя, не найденным ранее утверждённым маршрутом. В этой редакции изменены границы выпусков и зависимости:

- 0.7 сосредоточена на производстве согласованной подачи и PDF-томов. Импорт дерева папок перенесён к массовому приёму/обработке в 0.8.
- 0.8 объединяет приём материалов, извлечение/OCR и поиск. Структурные производные PDF относятся сюда же; существующая перестановка страниц используется без повторной реализации.
- **Командная основа приходит в 0.9, до совместной проверки.** Аннотации, назначения проверяющих и обсуждения 0.10 сразу строятся на участниках/правах/ревизиях, вместо отдельной локальной системы с последующей переделкой.
- Сравнение содержания переходит в 0.10: поиск/OCR уже дают текст/координаты, сервер — общие версии, а пользователь принимает решение в одном процессе проверки.
- Общий центр операций и управление местом завершаются в 0.11 вместе с автономными копиями. Они не откладываются целиком на 1.0.
- Дополнительные источники появляются в 0.12 до слушаний. 0.13 использует готовые источники и занимается показом/выдачей.
- 1.0 получает оставшиеся функции установки, обновления и администрирования; проверка всей линии обязательна, но не считается отдельным функциональным объёмом.

Это предлагаемое распределение для принятой цели. Ранее принятые требования сохраняются; предложения из обзора аналогов не выдаются за ранее утверждённые функции. Внешний хостинг, платные аккаунты, модели и передача данных не разрешаются автоматически. Даты и человеко-дни пока не назначены: нет выбранных конфигураций и измеренной трудоёмкости новых архитектурных рубежей.

Регрессии существующего поведения обязательны при его изменении, но не увеличивают оценку новой разработки. Критерии «два разных номера, выборочно обновлена одна подача, вторая и старые ZIP неизменны» уже реализованы и остаются инвариантами, а не новой функцией каждого выпуска.

## Общие контракты и зависимости

1. **Сохранность.** Исходники и старые ZIP/снимки неизменны. Неподдержанные элементы Word не удаляются ради успешного экспорта: понятный отказ и место проблемы, если оно определимо. Обозначение, префикс, номер, папка, имя и ID принадлежат подаче. OCR, глоссарий, сервер и синхронизация не принимают библиотечную версию автоматически. Импорт/поиск не запускают перевод.
2. **Локальная работа.** Самостоятельный режим не требует сервера, аккаунта, библиотеки, Word, AI или переводчика для независящих действий. Основной PDF требует конвертера, а не панели. Общий сервер подключается явно, существующие дела не выгружаются автоматически.
3. **Происхождение.** Постоянные ID и версии уже есть — использовать их. Для новых объектов добавить явные якоря версии/части/страницы/области и карту преобразований. Номер приложения/имя файла не ID. Источник старой цитаты не подменяется новой редакцией.
4. **Единая модель без двойной реализации.** До 0.7 определить расширяемый контракт производных/снимков/якорей; в 0.8 — текста/координат/заданий; в 0.9 — серверные адаптеры/ревизии/авторизацию. Не переносить весь продукт на новую БД ради первого тома; не открывать локальный API в интернет вместо серверного design.
5. **Права.** С 0.9 доступ проверяется для каждого файла/preview/OCR/поиска/diff/задачи/экспорта; позже для заметок/событий/AI/показа. Фильтрация только в интерфейсе недостаточна. Воспроизводимый кеш не обходит права исходника.
6. **Очереди и место с первого использования.** Каждый этап получает минимальные прогресс/отмену/атомарность/лимиты для своих новых операций. 0.11 объединяет существующие адаптеры, а не создаёт их заново. Оригиналы, правки, подтверждённый OCR и единственные результаты не кеш.
7. **Переводчики и AI.** Claude/Codex равноправны, личные CLI-сессии остаются на выбранном устройстве. Сервер не получает их из общего архива. Внешняя модель/платный API/передача документов требуют явного решения. Ручная работа остаётся без AI.
8. **Перенос с каждым новым типом данных (N42).** Добавлять сущность в архив при её появлении, не копить перенос до 1.0. Не переносить сессии/секреты/права другого сервера. Индекс пересоздаётся; ручные правки сохраняются. Самостоятельная копия не требует исходного сервера/библиотеки.
9. **Проверки с каждым выпуском (N41).** Приватность, нагрузка, ошибки/прерывания, нативные пакеты/суммы и перенос не откладываются на финал. Не повторять неизменённую установку Word и подтверждённую приёмку без причины. Реальный Word, Office-имитация, Windows/Mac и CI — отдельные статусы.
10. **Выпуск.** Сценарий закончен только после проверки результата/архива/ошибок. Готовность кода, PR, merge и публикация различаются. Без отдельного указания не объединять PR и не публиковать GitHub Release.

## 0.7.0 — согласованная подача и PDF-тома

**Результат 14 ноября:** N03–N08 выполнены, три нативных пакета/обмен архивами/LibreOffice на двух Mac/переходы SumatraPDF проверены. [OpenSpec 34/34](../openspec/changes/archive/2026-11-14-submission-pdf-volumes/tasks.md), [отчёт](PDF-VOLUMES-VALIDATION.md). Настоящий Word 0.7.0 и внешние Mac-просмотрщики не подтверждены; конкретные оставшиеся шаги приведены в отчёте. Это готовность кандидата, не факт публикации.

**Результат:** уже подготовленные материалы превращаются в согласованный комплект с отдельными файлами и одним/несколькими PDF-томами. Новый массовый импорт сюда не примешивается; B04/B06/B09/B11/B17 используются.

### Новый объём и порядок

1. **План назначений и профили (N03/N04).** Именованные версионированные профили обозначений/языковых меток/штампов/ссылок/локаторов/имён. Существующая иерархия и preview остаются. Явно менять занятые номера/обмен номеров, сохраняя местные исключения и защищённые ручные имена.
2. **Согласование представлений (N04).** Один план изменений каталога/путей/перечня и управляемых упоминаний DOCX. Word использует существующие updatePlan/applyUpdates. Ручной текст — список для решения, не глобальная замена. Проверка ревизии на каждом шаге; при раздельном применении к живому Word честно видны незавершённые действия. В текущем коде нет общей транзакции с живым Word: design должен описать частичные шаги и безопасное завершение.
3. **Карта страниц и компоновка (N05/N06).** Часть/версия/страница/фрагмент → результат → том/страница. Основной документ опционален. Порядок/перевод/пропуски/форматы листа согласованы с отдельными PDF; длина самого перечня участвует в расчёте до устойчивого результата.
4. **Навигация и тома (N07/N08).** Общие номера с настройкой начала/вида/места без наложения, закладки/внутренние цели/локаторы/возврат. Явное разделение по пределам, правило слишком большого приложения, межтомовые ссылки без абсолютных путей. Прочие внешние ссылки не теряются.
5. **Фиксированный результат.** Расширить текущие preview/manifest/историю на тома, страницы и профиль. Изменения помечают устаревший снимок. При сбое остаётся старый ZIP; неполный том не готовый. Формы/шрифты/аннотации не теряются молча. Подписанный ready PDF хранится отдельно неизменным, подпись не приписывается новому тому.

**Первый законченный срез:** подготовленные PDF + нынешний перечень → один том с проверенными страницами/закладками, обычный ZIP рядом. Затем профили/перенумерация и основной DOCX; затем несколько томов. Модель страниц — до реализации срезов.

**Приёмка:** Annex/Exhibit в двух подачах → изменить занятые номера в одной → проверить DOCX/Word-обновление, отдельные PDF/перечень/том → перейти по ссылкам → перенести папку/архив на другую ОС. Исходники/старые ZIP/вторая подача совпадают по суммам. Отдельно кириллица/пробелы/#, изменение Word после preview, ручной текст, формы/подписи, коллизии, нет места/отмена/закрытие. Реальные переходы в новых томах проверяются настоящими просмотрщиками.

**Решения design:** профиль/якоря, способ компоновки/сохранения элементов, ограничения Word-транзакции и томов. Сложность высокая; тесты/пакеты не входят в оценку как новые функции.

## 0.8.0 — приём и поиск материалов

**Результат:** папка с текстовыми и сканированными PDF становится проверенным каталогом с поиском и пригодными производными. Готовые механизмы библиотеки/дубликатов/ручных пар используются.

### Новый объём и порядок

1. **Входящая структура (N01/N02).** Предварительная таблица дерева папок/путей/размеров/ролей/ошибок до записи. Объяснимые предложения оригинал–перевод, подтверждение/массовое исправление; имя не доказывает пару. Повторный импорт/дубликат старой версии разрешаются нынешними явными действиями, включая материал вне текущей страницы.
2. **Текст и OCR (N09/N10).** Представление страницы/координат/языка/метода/хеша исходника. Смешанные PDF, ненадёжный текстовый слой, ориентация/поворот/ограничение разрешения на копии. Выбор документа/страниц, надёжный текст не заменяется автоматически. Локальный движок/лицензии/пакеты для трёх платформ; предложенный начальный минимум RU/EN, остальные по матрице.
3. **Коррекция (N11/N13).** Скан рядом с текстом, сомнительные места/ошибки страниц, исправления/подтверждение с историей. Фрагмент содержит/индексирует только включённую область. OCR можно явно выбрать для перевода, без автоматического перезапуска перевода/версий.
4. **Новые производные PDF (N10/N43).** Существующий выбор/перестановка и перевод+оригинал остаются. Добавить явные поворот/произвольное объединение/разделение и публикацию производной с происхождением. Отдельный PDF с поисковым слоем по проверенному способу; формы/подписи/внешний вид не теряются молча. Неподдержанный способ не выдаётся за готовый.
5. **Полнотекстовый поиск (N09).** Оригинал/перевод/OCR/основной DOCX, слова/фразы/несколько слов/регистр/RU/EN. Фильтры источника/меток/версии/области, контекст/подсветка, точная страница/область. До конвертации DOCX — абзац/сноска, а не выдуманная PDF-страница. Старые/скрытые включаются явно; номера разных подач не смешиваются; карта тома только для совпавшего снимка.
6. **Жизненный цикл.** Версионированный индекс/результат OCR, incremental update/переиндексация без сети. Видимая неполнота вместо ложного отсутствия совпадений. Статус/отмена/checkpoint/лимит места для OCR/индекса; ошибку страницы изолировать. Пакеты языков проверяются при загрузке, затем работают offline. Подтверждённый OCR/правки в архиве доступны без движка, одинаковое содержимое не требует нового OCR.

**Первый срез:** смешанный PDF → OCR одной страницы → исправить → найти слово → перейти к области → сохранить/восстановить без сети. Затем дерево папок/пары, производные и большие очереди.

**Приёмка:** входящая папка → проверенные пары/дубли → OCR → ручная коррекция → поиск → производный материал → библиотека → импорт в подачу → том → перенос Windows↔Mac. Проверить потерю процесса, плохой язык/шум/таблицы, повреждение одной страницы, полный диск, изменение исходника, отсутствие исключённого текста в поиске/экспорте. Результаты не меняют вторую подачу/старые ZIP.

**Решения design:** движок/языки/ресурсы/координаты, индекс и происхождение производных. Контракты подготовить к серверной фильтрации 0.9; не объявлять локальный поиск проверкой командных прав. Сложность высокая.

## 0.9.0 — общие дела команды

**Результат:** несколько пользователей работают онлайн с одним делом и независимыми подачами по проверенным правам; сервер можно восстановить. Базовая безопасность нужна уже здесь.

### Новый объём и порядок

1. **Серверная модель (N19/N22/N28).** Пространство/участник/дело/материал/версия/подача/снимок. Отдельные серверные адаптеры БД/объектного хранения/задач, ревизии/условная запись/идемпотентность и проверка файла до публикации. Локальные ID/происхождение сохраняются; общий JSON/локальный RLock не серверная транзакция.
2. **Вход и права (N20/N21).** Приглашение/восстановление/сессия/отзыв; администратор/ведущий/редактор/проверяющий/читатель/внешний доступ — конкретная таблица полномочий в design. Все маршруты/задачи/preview/поиск/дедупликация контролируют объектный доступ. Нет утечки закрытого дела через совпадение/счётчик/старую ссылку.
3. **Полезная онлайн-работа (N22/N28).** Два клиента наполняют общее дело, создают подачи, выбирают версии и собирают комплект. Одновременное изменение показывает конфликт, не затирает запись. Новая версия доставляется в общую библиотеку, но в подачу принимается явно; старые ZIP независимы.
4. **Аудит (N23).** Автор/время/ревизия/результат, изменения доступа/решения/выдача. Без содержимого дела/секретов в журнале, понятная граница защиты от администратора. Снимок фиксирует точные версии и автора.
5. **Развёртывание и резерв (N24).** Проверяемая конфигурация TLS/входа/БД/хранилища/задач, bootstrap администратора без общего пароля, базовые квоты/ограничения PDF/архивов и изоляция конвертера/OCR. Согласованный backup БД+объектов+ключей, восстановление отдельного экземпляра, целостность и совместимость протокола.

**Первый срез:** сервер + два участника → общий материал в двух подачах → новая версия только в одной → экспорт → запрет третьему → restore на другом сервере. Затем остальные роли/поиск/аудит/конкуренция.

**Приёмка:** разные процессы сервера/клиентов, два редактора/запрещённый пользователь, конфликт одного поля, обрыв/повтор загрузки, смена прав в задаче, чужой ID/путь/старое приглашение/ссылка, поиск закрытого OCR. Полный backup/restore с прежними результатами; локальная подача работает без сервера. Online не подтверждает offline-sync следующего этапа.

**Решения design до кода:** threat model, изоляция, транзакционная БД/файлы/идентификация/TLS/секреты/backup/схема адаптеров. Self-hosted — предложенная отправная точка, внешний провайдер/расходы не выбраны. Нынешний локальный API не открывается в интернет. Сложность очень высокая.

## 0.10.0 — совместная проверка и переводы

**Результат:** команда сравнивает редакции/переводы, обсуждает замечания и принимает решение по конкретной версии, затем готовит безопасную выдачу. Локальная личная проверка тех же материалов доступна без сервера.

### Новый объём и порядок

1. **Сравнение содержания (N12).** Использовать текущий compare состава и версионированный текст/координаты 0.8. Добавить текстовый/визуальный diff, выравнивание вставленных/удалённых/переставленных страниц, две зафиксированные версии рядом. Отличать OCR/layout от изменения исходника, неоднозначности не угадывать. Из diff — переход к точному источнику.
2. **Глоссарий/память и качество (N14/N15).** Термины/имена/языки/контекст/версии/происхождение, экспорт правил отдельно от дела. Память только подтверждённых сегментов. Оригинал рядом с переводом, полнота/числа/даты/имена/термины/переполнение/источник OCR. Новое правило предлагает изменения, не переписывает утверждённые PDF.
3. **Пакетный перевод (N16).** Использовать отмену/сохранённые части/правки/resume одиночного материала. Новое — выбор нескольких материалов/языка/провайдера/правил, preview общей отправки, приоритеты/лимиты/состояние очереди и повторы неуспешных частей. Устройство/исполнитель явные; личные CLI-сессии не копируются на сервер.
4. **Аннотации и проверка (N17/N27).** Отдельный слой выделений/заметок с якорями версии/страницы/области. Перенос якорей предлагает соответствия, показывает потерянные. Назначения/обсуждения/решения по версии с учётом прав 0.9; поздняя правка не подменяет одобренную версию. Личные заметки не становятся общими автоматически.
5. **Осознанное принятие общей версии (N28).** Diff/замечания/подтверждённый перевод ведут к нынешнему выборочному update_apply, а не второму механизму импорта. Сохраняются местные назначения/правки/вторая подача. Общий глоссарий и «где используется» учитывают область доступа.
6. **Безопасное скрытие (N18).** Производная версия с удалением скрываемого текста/объектов/метаданных/вложений; не чёрная маска. Проверить извлечение/OCR/поиск/preview/буфер и состав разрешённого экспорта. Полный архив с оригиналом не обезличенная выдача. Исходник сохраняется под прежними правами.

**Первый срез:** две версии материала → content diff → замечание проверяющего → исправление → решение → принятие в одну подачу → комплект. Затем глоссарий/пакетный перевод и безопасная производная.

**Приёмка:** два участника проверяют OCR/перевод, пропуск/число/термин, изменённую страницу и потерянную аннотацию → пакетный сбой/продолжение без потери правок → утверждение версии → выборочное обновление → скрытие/выдача без исходника. Проверить запрещённого участника/позднюю правку/старый якорь/извлечение скрытого. Claude/Codex и локальный/общий режимы проверяются отдельно.

**Решения design:** якоря и статусы решений, контроль доступа к комментариям/глоссарию, движок diff и проверяемый способ redaction. Если безопасное удаление не подтверждено, выдача блокируется; строка остаётся открытой. Сложность высокая, redaction — отдельный риск.

## 0.11.0 — автономная команда и управление данными

**Результат:** участники продолжают работу offline и согласуют изменения без потерь; пользователь видит, что отправляется, выполняется и занимает место. Локальный одиночный режим уже существует — это новый режим автономной **командной копии**.

### Новый объём и порядок

1. **Обмен (N25).** Явная область копии, дельта-курсор/журнал операций/ID/ревизии/совместимость. Докачка больших файлов с хешами, идемпотентность, offline-очередь; статусы «локально/ожидает/конфликт/синхронизировано/недоступно».
2. **Конфликты (N26).** Одновременные реквизиты/перевод/комментарий/номер/путь, удаление против правки, пересечение имён. Оба варианта/происхождение/последствия решения; без last-write-wins всего дела и двойной записи после потерянного ответа. Существующий выборочный импорт версий сохраняется.
3. **Доступ и устройства (N26/N28).** Сервер снова проверяет права при отправке, срок автономного допуска, отзыв/управление локальной копией. Скачанный файл нельзя гарантированно отозвать: явная политика, не обещание стирания чужого диска. «Где используется» отличает известные серверные данные от неизвестной offline-копии.
4. **Совпадения (N35).** Только точные совпадения доступных дел/версий, названный материал и версия. Раздельные происхождение/права; физическая экономия не объединяет сущности и не раскрывает закрытое.
5. **Общий центр операций (N38).** Адаптеры нынешних library/translation jobs и новых томов/OCR/индекса/сети/backup: стадия/владелец/ресурсы/очередь/отмена/повтор/продолжение. Не переписывать рабочий одиночный resume. Внешний процесс без checkpoint не обещает возобновление в середине.
6. **Обзор места (N39).** Размер источников/версий/экспортов/cache/индекса/offline-копий, квоты/резерв, предварительная очистка с восстановимостью/активными заданиями/закреплёнными результатами. Удаление истории/архива отдельно явно. Подтверждённые правки/OCR/единственные результаты не мусор.

**Первый срез:** два клиента offline с независимыми правками → reconnect/докачка → один конфликт → явный выбор с сохранённой альтернативой → обновить одну подачу. Затем отзыв/тяжёлые файлы/общий обзор операций и диска.

**Приёмка:** разный порядок reconnect, пропавший ответ/повтор, отзыв прав во время offline, удаление против правки, полный диск/обрыв файла/старый клиент → разрешение → две подачи/старые ZIP/ручные правки и архив целы. Сетевой симулятор — автоматизация, реальные клиенты Windows/Mac — отдельная среда.

**Решения design:** протокол/ключи/offline-допуск/конфликты/хранение локальной копии. Сложность очень высокая; обмен ZIP/обновление списка по таймеру не закрывают её.

## 0.12.0 — исследование дела и другие источники

**Результат:** команда строит хронологию/связи с проверяемыми источниками, включая новые типы материалов. Ручная работа полезна независимо от AI.

### Новый объём и порядок

1. **Матрица источников (N32).** Основной DOCX уже поддержан, это не новая функция. Дополнительные документы/таблицы/презентации, изображения, письма/вложения, аудио/видео — отдельные варианты материалов. Для заявленного варианта: неизменный оригинал, безопасный preview/проигрывание, производная/извлечённый текст и происхождение. Не терять листы/вложения/дорожки/элементы. Матрица конкретных форматов/конвертеров/ограничений принимается в design; «любые Office/медиа» не обещается.
2. **Факты и события (N29).** Дата/интервал/неизвестная дата, участник/тема/спорность и несколько источников с версией/страницей/областью/при необходимости временем медиа. Факт, утверждение стороны и аналитическая заметка различимы. Источник меняется только через видимую повторную проверку.
3. **Представления (N29).** Хронология/таблица, связи/противоречия, фильтры/подборки и переход к источнику/diff, экспорт разрешённого среза. Старые привязки не подменяются новой редакцией.
4. **Семантический поиск (N33, предложение).** Версионированные embeddings/язык/явная модель и hybrid с обычным поиском; права до выдачи/контекста и отзыв. Результат содержит точный источник/фрагмент; похожесть не истинность.
5. **AI-черновики (N34, предложение).** Сводка выбранных материалов, предложения событий/противоречий/связей. Preview контекста/провайдера/передачи/стоимости; человек принимает отдельные предложения. Сохраняются входы/модель/источники/решение. Нет автоматического утверждения фактов/юридических выводов. Ненадёжный OCR видим.

**Первый срез:** несколько материалов разных поддержанных типов → ручные события/точные источники → подборка/экспорт. Затем семантика и проверяемый помощник, если принята их конкретизация.

**Приёмка:** спорная дата/несколько источников/новая версия → ручная хронология → поиск → AI предлагает ошибку → проверка/отказ → разрешённый срез/архив. Проверить закрытый источник, вымышленную ссылку, документную инструкцию, отказ модели/сети и неподдержанный элемент файла. Ручной путь/обычный поиск продолжают работать, частные документы не публичный benchmark.

**Решения design:** глубина форматов, модель/ресурсы/стоимость/допустимая передача, корпус качества. Транскрипция не считается автоматически обещанной словом «медиа» — отдельное решение матрицы. Не подменять сохранённое направление молчаливым исключением: при изменении объёма фиксировать решение пользователя. Сложность высокая с исследовательской неопределённостью.

## 0.13.0 — слушания и внешняя выдача

**Результат:** подготовленный снимок показывается на отдельном экране и передаётся участникам без внутренних данных. Новые форматы уже проверены в 0.12; не смешивать написание конвертеров с режимом слушания.

### Новый объём и порядок

1. **Подготовка сеанса (N30).** Подборки/порядок/ярлыки/страницы/версии/заметки ведущего, проверка наличия/прав/скрытия/места. Снимок фиксирован; новая библиотечная версия не меняет подготовленный набор.
2. **Ведущий и показ (N30).** Раздельные экраны, быстрый номер/страница, масштаб/фрагмент/сравнение/возврат. Служебные пути/диалоги/закрытые исходники/личные заметки не выводятся зрителям. Реальная проверка нескольких экранов/устройств требует отдельного разрешения на управление ПК.
3. **Offline-сеанс (N30).** Предзагрузка/проверка снимка, отсутствие сети, сохранение позиции/порядка и восстановление после старта. Тяжёлый файл/медиа не блокирует сеанс; поздняя синхронизация заметок не меняет опубликованный снимок.
4. **Ограниченная выдача (N31).** Названные внешние участники, конкретный снимок/права чтения/скачивания/срок/отзыв/журнал, watermark по явной политике. Публичная ссылка/сторонний обменник не возникают автоматически. Online-отзыв не отзывает скачанную копию.
5. **Состав выдачи.** Allowlist разрешённых производных/страниц/вложений; без оригиналов закрытых зон, личных комментариев, старого OCR/временных файлов. Пагинация/ссылки согласованы с томами; перенос без доступа к живому делу.

**Первый срез:** фиксированная подборка PDF → ведущий/отдельный показ → offline/restart → продолжение без утечки заметок. Затем все поддержанные источники и внешний доступ.

**Приёмка:** команда готовит закрытую/разрешённую версии → снимок → показ/сравнение на реальных экранах → сеть выключена/перезапуск → продолжение → внешний участник получает только разрешённое. Отдельно смена прав/истёкший срок/старый снимок/ошибка медиа, извлечение скрытого и сохранность полного закрытого дела.

**Решения design:** граница ведущего/выдачи, правила доступа/сроков/offline и матрица просмотрщиков. Совместимость со всеми судами/порталами не заявляется без их требований. Сложность высокая.

## 1.0 — установка, обновление и эксплуатация платформы

**Результат:** обычный пользователь и администратор устанавливают, обновляют и восстанавливают решение без сопровождения разработчика. Рабочие стартовый экран, данные вне программы, архивы, отдельные статусы и весь центр операций 0.11 повторно не разрабатываются.

### Оставшийся функциональный объём

1. **Установщик и конфигурация (N36).** Windows x64/Mac Intel/ARM, зависимости/порты/понятные отказы. GUI переноса существующего каталога с проверкой прав/места/целостности; конфигурация Word не зависит от тестовой распаковки. Серверный установочный путь/мастер конфигурации и безопасная передача администрирования. Удаление программы не удаляет дела без отдельного действия.
2. **Проверенное обновление (N37).** Канал/наличие версии/явное согласие, подходящий пакет/проверка происхождения и целостности, собственный экземпляр/перезапуск, совместимость клиентов/сервера. Оркестрация нынешнего backup/защиты схемы, прерывание/повтор/откат программы и данных. Старый клиент не пишет несовместимую схему; рабочая программа/данные остаются при сбое. Ручной путь сохраняется.
3. **Эксплуатационные политики (N24/N41).** Администратор задаёт расписание/retention резервов, проверку целостности/контроль восстановления, ротацию секретов и аварийный доступ. Используется backup 0.9, не второй формат. Состояние хранилища/очередей/ошибок без содержимого дела, диагностическая сводка/repair индекса/задач, понятный runbook потери сервера/диска/учётной записи.
4. **Канал Word (N40).** Принять конкретный production-путь Windows/Mac: сравнить локальный экспериментальный, управляемый организацией и Marketplace. Поставка/обновление/восстановление разрешения и Office/API-матрица. Аккаунты/подпись/хостинг/расходы — отдельные решения, а не автоматический выбор магазина. Основной процесс без панели.
5. **Стабильная поставка и контракты (N41/N42).** Версионированные API/архивы/профили и миграция от 0.6/промежуточных схем, независимый архив без секретов, лицензии/NOTICE/self-host/вклад Open Source, доступность клавиатуры/масштаба/состояний. Учебный пример расширен томом/сканом/поиском/командой. Матрица ОС/форматов/просмотрщиков/провайдеров и реальные пределы опубликованы.

### Итоговая приёмка, отдельно от нового объёма

Чистые клиент/сервер → два участника → импорт/OCR/перевод/проверка → один материал в двух подачах с разными обозначениями → offline-конфликт → версия только в одной → исследование/показ/ограниченная выдача → прерванное обновление → восстановленный сервер → независимый архив на другой ОС.

Проверяются оригиналы/старые ZIP/ручные правки, запрещённый участник, отсутствие Word/CLI/сети, полный диск, утечки через производные/поиск/AI/экран. Это обязательная интеграционная проверка, не ещё одна новая функция.

**Решения до реализации:** канал обновления/подписей/Word, поддерживаемая серверная конфигурация, нагрузка/retention/RPO/RTO и модель администрирования. Выбранные показатели измерить, не выдумывать. Новые прикладные сценарии требуют новых доказательств; старую опциональную проверку конкретного DOCX нельзя объявить новым обязательным барьером. Сложность высокая/очень высокая.

Не откладывать выбор ID/якорей до сервера, безопасность до 1.0, а место до переполнения диска. Не реализовывать все технические подсистемы заранее без законченного пользовательского среза.

По каждой новой функции перед кодом фиксируется: что переиспользуется → чего нет → какое поведение добавляется → зависимость → как доказать. Оценивать отдельно новый код, адаптацию существующего, исследования и проверки. Число строк/tasks не оценка трудоёмкости. Малый/рабочий/предельный искусственные корпуса и бюджеты CPU/RAM/места/сети/latency/пользователей задаются до тестов, результаты после; старый стресс-тест не предел новой платформы.

Все B01–B18 сохранены. Все N01–N43 имеют этап в сверке; N36–N42 распределены по этапам появления данных/операций, не отложены единым блоком. A01–A08 остаются явными решениями/историческими альтернативами: DeepL/коммерческий API/обменник не обязательные интеграции, полный паритет с неизвестными функциями аналогов не обещан, собственный совместный текстовый редактор Word не возникает неявно. Если он потребуется, вопрос не исчезает — оформляется отдельным архитектурным решением. Ни одно направление не снимается без записи решения пользователя.

## OpenSpec и выпуск

1. До реализации очередного выпуска создать через CLI одно или несколько зависимых изменений. Proposal связывает ID сверки/результат/совместимость/решения; design — архитектуру/риски; specs — наблюдаемое поведение/ошибки; tasks — порядок и доказательства. Не создавать фиктивно завершённые изменения и не переносить требования обратно в WORKSTATE.
2. Каждый срез: загрузка → новое действие → проверенный результат → комплект/выдача → независимое восстановление, включая отмену/ошибки/прерывание. Тесты искусственные, частные материалы вне Git, у артефактов есть размер/срок/очистка. Согласованное не пересогласовывать из-за переноса в OpenSpec.
3. До завершения — адресные регрессии/общий применимый набор/строгая валидация OpenSpec, настоящий интерфейс новых действий, необходимые реальные приложения, три нативных пакета/суммы/перенос и серверные проверки с 0.9. Различать симуляцию, автоматизацию и реальные среды; пользователю только действительно оставшиеся конкретные ручные шаги.
4. Сверить ID/код/спецификации/результаты/ограничения, синхронизировать и архивировать только завершённое. Подготовить PR/пакеты/серверную поставку/пользовательское описание. Merge/Release по отдельному указанию.
5. На стадии этого документа реализована **только переработка плана**. Новые функции не отмечены выполненными. Проверки кода 13 ноября подтверждают существующую основу, а не будущие версии.
