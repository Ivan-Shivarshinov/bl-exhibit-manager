# От 0.6.0 до 1.0: план командной платформы

Дата: 12 ноября 2026. Основание — [сверка исходного объёма и реализации](SCOPE-RECONCILIATION.md). База — опубликованная v0.6.0. Это новый предлагаемый маршрут, не восстановленная из истории утверждённая нумерация.

## Цель и статус решений

Пользователь выбрал **командную платформу**: подготовка и поиск материалов, OCR, переводы и версии, аннотации, слушания, совместная работа, права, синхронизация и серверная инфраструктура. Локальная подготовка без аккаунта, сервера и панели Word остаётся самостоятельным полноценным режимом. Windows и macOS, Claude и Codex равноправны.

Принятая цель отличается от предлагаемой разбивки и уточнений. Идеи из обзоров аналогов и прежних списков «не входит» помечены в сверке как предложения, а не задним числом утверждённые функции. Семантика, AI, другие форматы и расширенные PDF-действия включены в маршрут для рассмотрения, а не молча исключены. Конкретные расходы, внешние передачи данных и публикации этот план не разрешает.

Прежняя схема «PDF → поиск → OCR → эксплуатация локальной 1.0» заменена. Между 0.9 и 1.0 предусмотрены **0.10–0.13**: после версии 0.9 допустима 0.10. Так создание платформы не прячется в один финальный этап. Даты не назначены: без выбранной инфраструктуры, контрольной нагрузки и оценки первых изменений календарные обещания были бы выдуманными.

## Постоянные контракты

1. **Сохранность.** Оригиналы и старые ZIP/снимки неизменяемы. Производные имеют происхождение, версию и параметры. Неподдерживаемые элементы Word не удаляются ради экспорта; объясняются отказ и место проблемы.
2. **Независимые подачи.** Обозначение/префикс/номер/папка/имя/ID принадлежат подаче. Общая версия, OCR, глоссарий и синхронизация не перезаписывают их. Новая версия применяется только по preview и явной команде к выбранной подаче. Импорт/индексация не запускают перевод.
3. **Автономность.** Отдельная подача доступна без библиотеки, сервера, AI, переводчика и Word. Командный режим подключается явно; существующие дела не отправляются на сервер автоматически.
4. **Версии и ссылки.** Источник привязан к определённой версии/странице/производной, а не только к имени. Старая ссылка не открывает незаметно новую редакцию.
5. **Права везде.** Файл, preview, OCR, поиск, diff, аннотация, экспорт, событие и AI-контекст наследуют допустимую область. Скрытие кнопки не заменяет серверную проверку.
6. **Переводчики.** CLI работают на явно выбранном устройстве пользователя. Сессии/токены не попадают в общий архив/сервер. Общая очередь не даёт серверу личные аккаунты. Будущий API/облачная модель требуют осознанного выбора, без скрытого платного переключения.
7. **Долгие операции.** Владелец, стадия, лимиты, атомарная публикация, отмена и правило повтора/продолжения. Частичный результат не готовый; повтор команды не применяет изменение дважды.
8. **Место и приватность.** Предварительная оценка места, lifecycle индекса/preview/cache. Ручные правки, исходники и единственные результаты не кеш. Диагностика не содержит документов/поисковых запросов по умолчанию.
9. **Перенос.** Новые пользовательские сущности входят в независимый архив; воспроизводимые индексы пересоздаются. Исходный сервер/библиотека не обязательны. Секреты и чужие права не восстанавливаются как действующее разрешение.
10. **Доказательства.** Код, автоматизация, реальное приложение, подтверждение пользователя и выпуск различаются. Установка неизменённой панели и подтверждённые проверки не повторяются без новой причины.

## 0.7.0 — производство подач

**Результат:** принять структуру материалов и получить согласованные отдельные приложения и тома. Нынешние массовые действия/перечень B04/B15/B17 — база, а не новые функции.

### Порядок реализации

1. **Входящий пакет (N01/N02/N32).** Сканирование папки без записи, структура/пути/размеры/ошибки и роли в таблице. Объяснимые предложения пар, неоднозначности решаются человеком; имя не доказывает соответствие. Повторный импорт, дубликат прежней версии и совпадение за текущей страницей разрешаются явно. Сначала PDF; для Office/медиа заранее определить матрицу оригинал → preview → производная → ограничения.
2. **Переносимые профили (N03).** Версии профилей обозначений/префиксов, языковых меток, штампов/шрифта, ссылок/локаторов, имён и папок. Иерархия «профиль → подача → группа → местная правка», preview отличий. Смена профиля не стирает исключения; профиль переносится без документов.
3. **Согласованная перенумерация (N04).** Снимок назначений → план номеров/путей/управляемых упоминаний → проверка → атомарное применение. Стабильные ID, защита stale-плана, обмен номеров без промежуточной коллизии. Ручной текст не заменяется глобально: список мест для решения. Обычная загрузка DOCX обязательна; Word использует тот же план с проверкой версии документа.
4. **Карта страниц (N05/N06).** Оригинал/перевод/выбор/фрагмент/разделитель → готовая часть → том/страница. Основной документ необязателен; порядок, поворот, размеры и пропуски согласованы с отдельными файлами. Подписанный исходник сохраняется отдельно неизменным; пересобранный том не объявляется исходным подписанным PDF.
5. **Тома и навигация (N07/N08).** Текущий перечень, разделители, общие страницы, закладки, переходы/возврат, локаторы. Preview разделения по страницам/размеру и правило слишком большого одиночного приложения. Межтомовые ссылки без абсолютного пути. Обычный ZIP доступен независимо.
6. **Публикация результата (N38/N39/N42).** Preview состава/страниц, проверка целей/имён/готовности/места, manifest и снимок настроек в истории. Изменение подачи помечает результат устаревшим. Отмена/сбой сохраняют прежний комплект; частичные файлы не выдаются. Архив переносит профили/снимки.

**Первый срез:** готовые PDF + перечень → один том с внутренними переходами без основного DOCX. Далее папки/профили/перенумерация, несколько томов и полный путь DOCX. Модель страниц определяется перед этими срезами.

**Приёмка:** искусственная папка с кириллицей/пробелами/`#`, смешанными размерами и оригиналом/переводом → роли → профиль Annex → перенумерация → DOCX/отдельные PDF/два тома → реальные переходы → перенос на другую ОС. Другая подача остаётся Exhibit со своей версией; старые ZIP/исходники сверяются по суммам. Отдельно подпись ready PDF, неоднозначная пара, старый дубликат, занятое имя, мало места, прерывание и смена DOCX после preview. Реальные Word/PDF-проверки фиксируются по среде, Office-имитация их не заменяет.

**Сложность:** высокая: транзакция ссылок/каталога, модель страниц и два режима экспорта. Библиотека PDF, схема профиля и лимиты томов — решения design до кода.

**Сохранённые детали прежнего плана S10:** номер страницы настраивается по началу/виду/месту и проверяется на наложение; длина самого перечня участвует в расчёте страниц до устойчивого результата. Шрифты, формы, изображения и существующие аннотации не теряются молча. Не относящиеся к приложениям внешние ссылки сохраняются; одинаковые названия закладок не смешивают цели. Разделение на тома — новая явная настройка N08, а не скрытое изменение старого экспорта.

## 0.8.0 — содержание и сравнение

**Результат:** текст и сканы доступны одному поиску; новая версия проверяется по содержанию до применения. Поиск/OCR объединены, а не разделены ради номеров.

### Порядок реализации

1. **Текст и происхождение (N09/N10/N13).** Страница/координаты/язык, хеш исходной части, способ извлечения/движок/версия. Смешанные PDF и ненадёжный встроенный слой; оригинал неизменен. Повторный OCR явно выбран и не уничтожает исправления.
2. **Локальный OCR (N10/N11).** Выбрать движки/лицензии для Windows/Mac Intel/ARM, языковые пакеты, память/обновление. RU/EN — предложенный проверочный минимум, остальные по матрице. Поворот, очереди/checkpoint, отказ страницы и сомнительные места. Наличие OCR не доказывает качество.
3. **Поиск (N09).** Индекс оригиналов/подтверждённых переводов/OCR и основного DOCX. До конвертации DOCX показывать абзац/сноску, не выдумывать PDF-страницу. Слова/фразы/несколько слов, правила регистра и RU/EN, фильтры источника/меток/дела/версии, контекст с подсветкой и переход к месту. История/скрытые материалы включаются явно. Один материал под разными номерами не смешивает назначения; карта тома используется только для совпавшего снимка. Штамп и метаданные отличимы от текста источника.
4. **Коррекция/фрагменты (N11/N13).** Страница рядом с распознанным текстом, правки с историей и версия текста в поиске. Во фрагменте индексируется только включённая область; вырезанное не утекает в поиск/экспорт/буфер.
5. **Diff (N12).** Две фиксированные версии рядом, вставленные/удалённые/переставленные страницы, текстовые отличия и визуальное сопоставление сканов. Различать смену layout/OCR и содержания; дубли/неоднозначности не угадывать. Можно открыть исходные части/страницы. Принятия новой версии автоматически нет.
6. **Жизненный цикл (N38/N39/N42).** Инкрементальное обновление/скрытие, неполный поиск, миграция/переиндексация. Индекс воспроизводим, ручной OCR — данные. Отмена/закрытие/повреждение/нет пакета или места оставляют доступ к прежнему. Контракт готовится к правам 0.10, которые ещё не считаются реализованными.

**Приёмка:** текстовый PDF/скан/смешанный → поиск → страница/фрагмент → исправление OCR → явная передача текста на перевод → версия с перестановкой/добавлением страниц → diff → обновить только Annex-подачу → том/ZIP. Второй проект/старые экспорты неизменны. Архив Windows↔Mac сохраняет правки, пересоздаёт индекс без перевода. Проверить плохой скан/язык, частичный OCR, прерывание и отсутствие исключённого текста.

**Сложность:** высокая: координаты/версии, многоязычность и ресурсы. На корпусе измеряются полнота извлечения, OCR, задержки/память; численные бюджеты задаются в design до проверки, без выдуманных процентов.

**Сохранённые детали OCR из S10:** выбрать весь документ или страницы; надёжный текст не заменять автоматически, обработку изображения вести на копии с пределом разрешения/памяти. Установка языков из приложения проверяет целостность загрузки; после установки OCR и восстановление индекса работают без сети. Повторное использование того же содержимого не требует повторного OCR. Подтверждённые текст/правки доступны из архива без установленного движка. Предусмотреть **экспорт производного PDF с поисковым слоем**, отдельного от оригинала: до реализации зафиксировать способ и ограничения форм/подписей, проверить внешний вид и отсутствие потерь; не объявлять неподтверждённый способ готовым. Корпус включает таблицы, шум, поворот и смешанные страницы. Неиндексированная страница видна как неполнота поиска, а не как отсутствие совпадения; ошибка одного файла не блокирует весь каталог.

## 0.9.0 — проверка материалов и переводов

**Результат:** проверка, терминология и комментарии сохраняются, выдаваемая производная не раскрывает скрытого. Существующий редактор B07 не выдаётся за новую функцию.

### Порядок реализации

1. **Глоссарий/память (N14).** Термин/вариант/имя, языки, контекст, версия/происхождение, импорт/экспорт отдельно от документов. Память только из подтверждённых сегментов; совпадение не доказывает пригодность в новом контексте. Новое правило показывает затронутые места, не переписывает старые переводы.
2. **Контроль перевода (N15).** Сегмент рядом с оригиналом, полнота/числа/даты/имена/термины, переполнение/разрывы и источник OCR. Замечание отличается от технической ошибки, решение относится к версии. Правка требует проверки нового результата, прежний PDF сохраняется.
3. **Пакетная очередь (N16/N38).** Материалы/страницы/язык/провайдер/правила и preview отправляемого объёма. Параллелизм/лимит аккаунта, отмена, повтор сегмента и продолжение после перезапуска. Claude/Codex проверяются отдельно. Без скрытого платного API и передачи личных сессий серверу.
4. **Аннотации (N17).** Выделения/комментарии/метки на версию/страницу, текстовые/координатные якоря. Новая версия предлагает соответствия и потерянные якоря. Отдельный слой; явное включение в экспорт. Личные заметки не попадают в общий комплект.
5. **Производные PDF (N43).** Поворот/перестановка/объединение/разделение, preview и новая версия с происхождением. Не переписывать оригинал; порядок инвалидирует затронутые локаторы и проверки.
6. **Скрытие данных (N18).** Производная с обзором зон; удаляются текст/объекты/метаданные/вложения, а не рисуется чёрная маска. Проверка извлечения/поиска/OCR/preview/буфера. Оригинал доступен только отдельно уполномоченному. Полный архив с оригиналом нельзя выдать как обезличенный файл.

**Приёмка:** OCR → термины → каждый CLI отдельно → замечания о числе/пропуске → ручная правка/подтверждение → аннотация → скрытие зоны → разрешённый том/выдача. Невозможность извлечь скрытое, сохранность закрытого оригинала, второй подачи/старого ZIP. Сбой CLI не теряет черновик, термин не меняет утверждённый перевод; архив сохраняет правки/заметки по выбранной области.

**Сложность:** высокая, redaction — отдельный риск утечки. Если удаление не проверяется, выдача блокируется; косметическая маска не закрывает N18. Командная проверка 0.11 использует эту модель без повторного создания хранения.

## 0.10.0 — работа команды на сервере

**Результат:** развёртываемая Open Source система с общим делом и проверяемой изоляцией. Не только вход или схема БД.

### Архитектурный рубеж

Нынешний локальный API нельзя просто открыть в сеть. До кода — threat model и design серверного режима: постоянные ID/ревизии, транзакционная БД, неизменяемые файлы с хешами, исполнители задач, авторизация и аудит. Локальный формат — адаптер/миграция с резервом. Self-hosted — исходное предложение; платный управляемый хостинг не выбран.

### Порядок реализации

1. **Сервер/данные (N19/N22/N28).** Пространство/организация, дела, участники, версии, подачи/снимки. Транзакции, файл проверяется до публикации метаданных, идемпотентность команд, фоновые задачи. Клиенты не пишут в один общий локальный JSON.
2. **Вход/устройства (N20).** Приглашение/активация, аутентификация, сессии/отзыв, восстановление, bootstrap администратора без общего пароля. Выбрать учётные записи/OIDC, требования MFA по угрозам, TLS/секреты/ограничения входа. Провайдер не означает одобрение расходов.
3. **Права (N21/N31).** Предложены администратор пространства, ведущий дела, редактор, проверяющий, читатель, внешний участник; таблица полномочий в design. Контроль объектов/файлов/preview/поиска/счётчиков/экспорта/задач. Дедупликация не раскрывает наличие закрытого дела.
4. **Онлайн-работа (N22/N28).** Два клиента добавляют материалы, создают подачи, выпускают версии/комплекты. Условная запись по ревизии, конфликт без затирки, уведомления. Сетевая доставка версии не применяет её к подаче.
5. **Аудит (N23).** Автор/действие/ревизии/время/результат, изменения доступа/решений. Без полных документов и секретов в журнале. Снимки комплектов привязаны к входным версиям/автору и целостности. Честная граница защиты журнала от администратора.
6. **Деплой/backup (N24/N36/N37).** Конфигурация, миграция/резерв, TLS/хранилище/очередь, health без утечек. Согласованный backup БД+объектов+ключей и восстановление другого экземпляра. Матрица протокола, несовместимый клиент не пишет данные.
7. **Ресурсы/задачи (N38/N41).** Квоты/параллелизм, лимиты архивов/PDF и изоляция конвертера/OCR. Задача отозванного участника не выдаёт запрещённый результат. Local-access tests не подтверждают серверную безопасность.

**Первый срез:** сервер + два участника → материал в двух подачах → версия принята в одной → экспорт обоих → третьему отказано → восстановление другого сервера. Затем остальные операции/поиск/роли/аудит до полного объёма.

**Приёмка:** разные процессы сервера/клиентов, два редактора и запрещённый участник; конфликт поля, одновременная загрузка/экспорт, отзыв во время задания, старое приглашение/ссылка, чужой ID, поиск закрытого OCR, повтор запроса и обрыв записи. Backup/restore с OCR/заметками/старыми ZIP; локальная подача работает без сервера. Онлайн-проверка не подтверждает offline-sync 0.11.

**Сложность:** очень высокая, новый класс архитектуры. БД/хранилище/вход/изоляция/backup оформляются решениями design до реализации. Один успешный вход или контейнер не означает готовность платформы.

## 0.11.0 — синхронизация и совместная проверка

**Результат:** автономные правки не теряются; новые общие версии не меняют подачу без решения. Синхронизация доставляет допустимые данные/операции, а не автоматически принимает оформление/перевод.

### Порядок реализации

1. **Протокол (N25).** Явный выбор области локальной копии, ID/ревизии, журнал операций, idempotency/курсоры/схемы. Статусы «локально/отправка/конфликт/синхронизировано/недоступно». Хеши/части загрузки, предел диска, продолжение больших файлов.
2. **Конфликты (N26).** Реквизиты/перевод/аннотации/номера/папки, удаление против правки, одинаковые имена. Оба варианта/происхождение и последствия выбора; без last-write-wins всего дела и двойного применения после reconnect. Отмена объединения безопасна.
3. **Отзыв (N21/N26).** Права повторно проверяются при отправке, срок offline-допуска, отзыв сессий и управление cache. Уже скачанное нельзя гарантированно забрать обратно: явное ограничение политики, не обещание удалённого стирания.
4. **Проверка командой (N27/N17).** Исполнитель/проверяющий на версию, обсуждения/ответы/решения. Поздняя правка не подменяет одобренную версию. Блокировка/передача DOCX и новая редакция; собственный совместный текстовый редактор не обещается неявно (A07), существующие возможности Word сохраняются.
5. **Общие версии/термины (N28/N14/N16).** Глоссарии/версии/заметки, «где используется» отличает известный сервер от неизвестной offline-копии. Принятие версии в одной подаче сохраняет её Annex/номер/путь/ID. Задание перевода имеет явного исполнителя/устройство, личные CLI-сессии не копируются.
6. **Межпроектные совпадения (N35).** Точные хеш-совпадения доступных проектов/версий, названный материал и версия. Логические сущности/права раздельны; экономия файлов не объединяет доступ. Похожесть не точный дубль; закрытый проект не виден через предупреждение.

**Приёмка:** два устройства → общая копия → оба offline → разные/конфликтующие правки → серверная версия → отзыв одного участника → reconnect в разном порядке с потерей ответа/повтором → разрешение конфликтов → одна подача обновляется, вторая остаётся прежней → проверка исходников/старых ZIP/правок. Отдельно мало места, частичный PDF, старый клиент, две копии CLI-задания. Симулятор сети — автоматизация; настоящие клиенты Windows/Mac учитываются отдельно.

**Сложность:** очень высокая: распределённая запись и offline-безопасность. Таймер обновления каталога или обмен ZIP не закрывают выпуск.

## 0.12.0 — исследование дела

**Результат:** доказуемая картина дела из источников. Хронологии — прежнее направление S04; семантика/AI — предложения N33/N34, детали/расходы ещё не приняты.

### Порядок реализации

1. **Факты/события (N29).** Даты/интервалы/неизвестная дата, участники/темы, спорность и несколько источников с версией/страницей/областью. Факт, утверждение стороны и заметка различаются. Ручной путь полезен без AI.
2. **Представления (N29).** Хронология/таблица, фильтры/связи/противоречия, переход к источнику/diff. Новая версия показывает устаревшую привязку, а не меняет цитату. Экспорт разрешённого среза; подборки используются в 0.13.
3. **Семантика (N33).** Версии embeddings, явная локальная/внешняя модель, язык, hybrid с обычным поиском, без скрытого перевода. Права до выдачи/контекста, отзыв и версии. Ссылка на точный фрагмент; похожесть не достоверность факта.
4. **Помощники (N34).** Черновик сводки выбранных материалов, предложения событий/связей/противоречий. Preview объёма/провайдера/стоимости, разрешённый контекст, без записи в утверждённое. Человек принимает/отклоняет отдельные предложения; источники/модель/входы/решение сохраняются. Политика ненадёжного OCR.
5. **Проверяемость (N21/N23).** Корпус с известными фактами/ложными совпадениями и инструкциями в документе, пытающимися управлять моделью. Проверять вымышленные ссылки/чужие данные; недоказанное остаётся черновиком. Пропавший источник требует проверки; отказ модели не блокирует ручную работу.

**Приёмка:** версии/сканы → ручные события/неоднозначные даты → поиск по смыслу → спорное AI-предложение → проверка источника/отказ → доказанный срез → ограниченный доступ/экспорт/перенос без закрытых источников. Перевод не меняется; AI-черновик не становится доказательством автоматически. Частные документы не публичный benchmark.

**Сложность:** высокая с исследовательской неопределённостью. До кода — модели/ресурсы и измеримые критерии на искусственном корпусе. CLI-подписка перевода не считается неограниченным серверным AI. Невозможность качества требует явного решения, не удаления строки из плана.

## 0.13.0 — слушания и выдача

**Результат:** разрешённый снимок используется на слушании/передаётся участникам без внутренних данных. Новое поведение поверх подготовки подач.

### Порядок реализации

1. **Подготовка (N30).** Подборка/порядок/ярлыки, страницы/версии и заметки ведущего. Фиксированный снимок, проверка файлов/прав/скрытых зон/диска. Обновление библиотеки не меняет готовый набор.
2. **Показ (N30/N07).** Отдельные экраны ведущего/выдачи, переход по обозначению/странице, масштаб/фрагмент/сравнение/возврат. Наружу не попадают системные диалоги, пути, личные заметки и закрытый оригинал. Проверка на двух настоящих экранах/устройствах — отдельное разрешение, не подразумеваемое планом.
3. **Offline-сеанс (N30/N25).** Предзагрузка снимка, работа без сервера, позиция/порядок и восстановление после старта. Поздние заметки не меняют опубликованный снимок; тяжёлый файл/обрыв медиа не блокирует показ.
4. **Выдача (N31).** Конкретная версия подборки/тома для названных участников, чтение/скачивание/срок/отзыв/журнал, watermark по явной политике. Онлайн-отзыв отличается от скачанной копии. Нет автоматического обменника/публичной ссылки.
5. **Источники (N32).** Реализовать матрицу 0.7: распространённые документы/таблицы/презентации, изображения, письма/вложения, аудио/видео. Для поддержанного варианта: оригинал, безопасный preview/воспроизведение, производная; в выдаче PDF/вложение или исходное медиа с ограничениями. Не терять молча листы/дорожки/вложения/элементы. Транскрипция и любой произвольный формат не обещаются одним словом «медиа»; глубина фиксируется в design.
6. **Состав/история (N06/N17/N18/N42).** Выдача по allowlist разрешённых сущностей: без закрытых источников, личных комментариев, старого OCR/временных файлов. Ссылки/страницы/скрытие согласованы с томом. Перенос не требует живого дела.

**Приёмка:** PDF/скан/другие источники → закрытая и разрешённая производная → снимок → отдельный экран с разрешённым сравнением → сеть выключена/перезапуск → продолжение → внешний участник получает именно снимок. Реальные файлы каждой заявленной разновидности, права и просмотрщики. Перед выпуском — матрица поддержанных/неподдержанных вариантов; словом «Office» N32 не закрывается.

**Сложность:** высокая: приватность экрана/выдачи и разнородные форматы. Не обещать совместимость со всеми судами/порталами без их требований.

## 1.0 — стабильная командная платформа

**Результат:** пользователь и администратор устанавливают/поддерживают/восстанавливают всё решение без разработчика. Это дополнение к B12/B13, не повтор ZIP/стартового экрана.

### Новый эксплуатационный объём

1. **Поставка (N36).** Клиент Windows x64/Mac Intel/ARM, данные независимо от распаковки приложения, настройки/зависимости/порт. Перенос каталога данных проверяет права/место/целостность, действующие настройки Word не зависят от тестовой распаковки. Сервер: установка, администратор, TLS/хранилище/резервы, безопасные значения/runbook. Удаление приложения не удаляет дела без отдельной команды.
2. **Обновление (N37).** Целостность/происхождение пакетов, канал/совместимость клиента и сервера, миграция/backup, обрыв/повтор/откат. Откат бинарного файла отличается от отката схемы; старый клиент не теряет неизвестные поля. Ручная установка остаётся; автоматическое скачивание/перезапуск включается явно.
3. **Центр операций (N38).** PDF/OCR/поиск/перевод/сеть/backup: стадия, владелец, ресурсы, очередь, отмена/повтор/продолжение. Без дублирования после восстановления. История ограничена, результаты сохраняются. Не обещать resume внутри внешнего процесса без checkpoint.
4. **Место (N39).** Исходники/версии/экспорты/cache/индекс/локальные копии, квоты/потребности, preview очистки/восстановимость, целостность ссылок и резервов. Ручная правка/уникальный результат не воспроизводимый мусор. Это функция продукта, а не очередной разовый скрипт.
5. **Канал Word (N40).** Сравнить локальный экспериментальный, управляемый организацией и Marketplace-путь по требованиям Microsoft; принять конкретный канал. Новые операции/разрешение проверяются в настоящем Word Windows/Mac; матрица Office/API вместо утверждения о неподдержке любых бессрочных версий. Издатель/подпись/хостинг/расходы — отдельные решения. Панель необязательна, повторная установка без причины не нужна.
6. **Эксплуатация/безопасность (N24/N41).** Потеря диска/ключа/доступа, повреждённый объект, недоступное хранилище; мониторинг без документов, обновление зависимостей, retention/журналы, ограничения конвертера/архива. Аудит серверной границы и sync. RPO/RTO выбираются в design и измеряются, не выдумываются.
7. **Стабильный контракт (N41/N42).** Версии API/архивов/профилей, матрица ОС/форматов/провайдеров, лицензии/NOTICE, self-host и вклад Open Source. Миграция от 0.6 и новых схем, независимый архив без секретов, восстановление без сервера. Клавиатура/масштаб/понятные ошибки, фоновые задачи не замораживают работу.

**Приёмка:** чистый клиент/сервер → два участника → импорт/OCR/перевод/проверка → материал в двух подачах с разными обозначениями → offline-конфликт → версия только в одной → хронология/показ/выдача → обновление с обрывом → новый восстановленный сервер → независимый архив на другой ОС. Проверить оригиналы/старые ZIP/правки/запрещённого участника/нет CLI и Word/диск/скрытые источники.

Отдельные статусы: нативная автоматизация, UI, настоящие приложения/устройства/сервер и ограничения. Опциональная проверка конкретного рабочего DOCX не становится обязательным барьером; новая командная функция не считается проверенной старым Windows-подтверждением.

**Сложность:** высокая/очень высокая, новые эксплуатационные функции плюс интеграционный рубеж. Если принятый объём не выполнен, нельзя объявить 1.0 только из-за назначенного номера.

**Сохранённые детали эксплуатации из S10:** безопасное обновление останавливает собственный экземпляр и при отказе оставляет рабочую программу/данные. Диагностика проверяет конвертер, оба CLI, OCR, права/место; предлагает восстановить производный индекс/прерванное задание без отправки документов в поддержку. Очистка не трогает активные задания; история/архивы удаляются отдельным явным действием. Учебный пример расширяется поиском/сканом/томом. Модель/языковой пакет не стирают принятый результат при обновлении; отключённый компонент не блокирует независящие действия.

| 0.13 | Выдача/экраны/форматы/просмотрщики/права/offline-снимок | Показ рабочего окна/выдача полного архива могут раскрыть закрытое. |
| 1.0 | Каналы обновления/Word/подписи, конфигурации, нагрузка/RPO/RTO/retention | Возможны аккаунты/сертификаты/инфраструктура; срок/стоимость до выбора не подтверждены. |

Принятый объём не согласовывается повторно из-за записи в OpenSpec. Платный аккаунт, внешнее размещение или новая передача данных не следуют из поручения на планирование. Альтернативы A02 (DeepL/коммерческий API/обменник) сохранены как варианты, а не обязательные интеграции. Полный паритет с аналогом неопределён без матрицы A05; это не основание исключить перечисленные направления. A07 сохраняет открытым вопрос собственного совместного текстового редактора, если он потребуется отдельно; N22/N26/N27 уже обеспечивают командную работу с материалами.

Сроки оцениваются после design/первого среза крупного рубежа. Бюджеты CPU/RAM/места/сети, задержки поиска/показа, число участников задаются **до тестов**, на небольшом/рабочем/предельном искусственном деле. Исторические стресс-профили не объявляются пределом нового сервера без измерения. Качественная сложность здесь не оценка человеко-дней; число строк задач не заменяет трудоёмкость.

## OpenSpec и доказательства готовности

1. Перед реализацией версии создать через CLI одно или несколько зависимых изменений. Proposal связывает ID N/A/B и результат/совместимость/решения; design — архитектуру/риски; specs — поведение/ошибки; tasks — порядок/доказательства. Изменения старых контрактов записываются явно.
2. Нельзя снять строку из-за старого «не входит в 0.5», дробить поиск/OCR ради номеров или назвать платформой список участников. Перенос отражается в обеих картах и решении пользователя; принятая функция остаётся открытой до проверки.
3. Каждый срез: загрузка → действие → результат → комплект/выдача → восстановление; ошибки/отмена/прерывание. Искусственные примеры, частные данные вне Git. Испытательные объекты имеют размер/срок жизни/очистку, бессрочные дубликаты пакетов не создаются.
4. До выпуска: адресные регрессии, общий применимый набор, `openspec validate --all --strict --no-interactive`, настоящий UI новых действий, необходимые реальные приложения, три пакета/суммы, серверные проверки с 0.10, обмен архивами и нагрузка. Office-имитация не настоящий Word; пользователю только оставшиеся конкретные ручные проверки.
5. Доказательства связаны с кодом/пакетом/средой. Сверить все ID/код/specs/результаты/ограничения. Выполненное синхронизировать/архивировать; на стадии планирования нет готовых новых версий. WORKSTATE краток, release notes только для пользователя.
6. Подготовить PR/пакеты/серверную поставку/описание. Объединение и GitHub Release только по отдельному указанию; принятие плана не автоматическая публикация.
