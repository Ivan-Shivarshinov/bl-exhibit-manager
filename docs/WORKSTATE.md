## Проверки и границы

- Финальный CI `35994695642`: Windows x64 / Mac Intel / Apple Silicon, 186 Python + 11 JS, сборка/запуск/перенос пакетов и взаимный обмен архивами. На обоих Mac — реальный LibreOffice, новая редакция и новый ZIP после восстановления; исходники/старая история неизменны.
- Локально настоящий Microsoft Word Windows: восстановленный проект принимает новую редакцию и собирает новый DOCX/PDF с относительными ссылками. Это не тест Office.js.
- Браузер Chromium/Playwright Windows: 1440×1000 и 900×900, сохранение → отдельное хранилище → восстановление → новый DOCX → новый ZIP; также конфликт, отмена и повреждённый архив. Нет ошибок приложения; намеренно повреждённый ZIP даёт ожидаемый 400. Browser plugin отсутствовал.
- Нагрузка на `768d8bf`: 537 МБ, создание 18,08 с, восстановление 9,48 с, пик выделений Python 4,13 МиБ; хеши сохранены. Подробности и проверяемые сценарии — в tasks change.
- Пользователь подтвердил прежнюю ручную проверку панели Word. Не просить повторять её. Коллеги сообщают замечания по мере поступления; формальный ответ не нужен, молчание не считается тестом.
- Единственный новый ручной сценарий: восстановить копию проекта с управляемыми ссылками; открыть копию исходного DOCX в Word; выбрать копию проекта в панели → «Проверить ссылки» → «Применить выбранные изменения». Проверить, что дальнейшее обновление названия относится к копии, а исходный проект и старые ZIP не меняются. Этот сценарий покрыт логикой импорта/JS, но не новым живым Office.js-тестом; по последнему указанию пользователя его прохождение обязательно перед возвращением v0.3.0 в Releases.
