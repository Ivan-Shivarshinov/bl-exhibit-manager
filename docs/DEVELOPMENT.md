# Разработка BL Exhibit Manager

[Главная страница](../README.md) · [Инструкция пользователя](PILOT.md)

## Запуск из исходников

Нужны Python 3.12 и Node.js 22.12+; Node используется только при сборке интерфейса.

Windows, PowerShell в папке проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
npm.cmd ci --prefix web
npm.cmd run build --prefix web
.\Start.cmd
```

macOS, Terminal в папке проекта:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
npm ci --prefix web
npm run build --prefix web
sh Start.command
```

Откроется `http://127.0.0.1:8765`. Повторный запуск использует работающий сервер. Закрытие вкладки не завершает сервер; остановка — `Stop.cmd` / `Stop.command`. Для диагностического запуска с остановкой через Ctrl+C:

```powershell
.\.venv\Scripts\python.exe -m uvicorn exhibit.app:app --host 127.0.0.1 --port 8765
```

На macOS используйте `.venv/bin/python`. Не публикуйте локальный сервер в интернете.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
npm.cmd run build --prefix web
node --test web/tests/*.test.js
```

На macOS замените пути Python и `npm.cmd` на `.venv/bin/python` и `npm`. Тесты используют временные папки и явные имитации моделей, не расходуют подписки. Word/LibreOffice, реальный вход и пользовательские переходы проверяются отдельно.

`python scripts/verify_feedback_office.py` проверяет настоящий установленный Word/LibreOffice на вымышленных сносках: полные названия, несколько документов в сноске, переносы строк, чёрный цвет ссылок, сохранение обычной ссылки на сайт и пути к PDF. Скрипт сохраняет готовый комплект и снимки страниц в `output/feedback-review/word`. В CI эта проверка запускается с LibreOffice на обоих вариантах macOS.

Структура: `exhibit/` — Python/FastAPI и документы; `web/` — React/Vite; `tests/` — тесты; `scripts/` — запуск и дополнительные проверки. Учебные материалы создаёт `python -m exhibit.samples`; результаты, документы, окружения и локальные настройки исключены из Git.

### Сборка дистрибутива

На целевой ОС установите `requirements-build.txt` в отдельное Python-окружение, соберите `web/dist`, затем выполните `python scripts/build_bundle.py`. Результат — `release/BLExhibitManager-<версия>-<платформа>.zip` и SHA-256. `python scripts/bundle_smoke.py <путь-к-ZIP>` проверяет распакованную сборку с отдельной папкой данных и без Python/Node в PATH, включая повторный запуск, PDF, экспорт, остановку и перенос приложения без потери проекта.

На Mac Intel `cryptography` собирается из исходников: на машине сборки нужны Xcode command line tools, Rust и Homebrew `openssl@3`. Устанавливайте зависимости командой `OPENSSL_STATIC=1 .venv/bin/python -m pip install --no-cache-dir -r requirements-build.txt` в чистое окружение. Для уже установленной динамической версии добавьте `--force-reinstall`. Статическая сборка исключает конфликт с SSL-библиотекой Python внутри приложения; `build_bundle.py` проверяет это перед упаковкой. На Apple Silicon готовое колесо уже содержит статический OpenSSL. См. [инструкцию cryptography](https://cryptography.io/en/latest/installation/#building-cryptography-on-macos). Эти инструменты нужны разработчику при сборке, а не пользователю готового приложения.

GitHub Actions выполняет тесты, нативную сборку и эти проверки на Windows, macOS Intel и macOS ARM. Это не заменяет ручную проверку скачанного пакета через защиту ОС, установленных office-программ и подписок на компьютерах участников, а также рабочих материалов. Пакеты включают Python и уведомления зависимостей в `THIRD-PARTY-NOTICES`; сервисы перевода и office-программы не включены.

Для воспроизводимой конвертации CI устанавливает LibreOffice 26.8.0 (полный номер 26.8.0.3) из официального архива с проверкой закреплённого SHA-256 для каждой архитектуры. `scripts/install_ci_libreoffice.sh` разрешён только на одноразовом macOS runner GitHub; это не установщик для пользователей. При обновлении тестового конвертера заменяйте версию и обе суммы вместе и прогоняйте проверки Office на обеих архитектурах. Приложение LibreOffice в наши пакеты не включается.

`python scripts/verify_revisions_office.py` проверяет обычный HTTP-путь без панели: ручные решения, две редакции DOCX, папки и неизменность ZIP с настоящим конвертером. `python scripts/verify_office_images.py` проверяет растровый EMF+, прозрачную искусственную подпись, оглавление и относительные ссылки. Результаты сохраняются только в `output/`.

## Локальная настройка Word

Пользователь выбрал локальное экспериментальное подключение для пилота ([решение и ограничения](WORD-INSTALLATION-OPTIONS.md)). Через «Помощь и настройка» → «Подключить панель» → «Разрешить и подключить» пакет сам готовит сертификат, порт и манифест, добавляет системное доверие и регистрирует панель. Только после явного согласия; системные запросы остаются видимыми. Ключ остаётся в папке данных; архивы проектов его не включают.

`word_install.py` повторяет регистрацию официального [office-addin-dev-settings](https://github.com/OfficeDev/Office-Addin-Scripts/tree/master/packages/office-addin-dev-settings): HKCU `Software\Microsoft\Office\16.0\WEF\Developer` с GUID панели на Windows, собственный файл в `wef` на Mac. Отладчик, SMB, политики организации и закрытие Word не используются. На Windows доверие добавляется в ROOT текущего пользователя; на Mac — в SSL/localhost политику пользовательской Связки ключей. Маркер владения хранит отпечаток и собственные объекты; конфликт не перезаписывается. Откат и удаление сохраняют чужие настройки, проекты и исходные файлы.

Для открытия создаётся каждый раз новый искусственный DOCX с taskpane/webextension, по модели [sideload Microsoft](https://github.com/OfficeDev/Office-Addin-Scripts/blob/master/packages/office-addin-dev-settings/src/sideload.ts). Присутствие подтверждается отдельным Office.js вызовом Word и ограниченными по времени сессиями; открытие страницы в браузере не объявляет подключение.

Для разработчика со своим сертификатом сохранён способ `python scripts/configure_word.py --cert <certificate> --key <private-key> --port 8769 --data-dir <isolated-data>`. Команда не устанавливает доверие ОС. Не запускайте её против чужого профиля. После настройки перезапустите локальное приложение.

`tests/test_setup.py` проверяет генерацию, повторную настройку, отказ доверия, занятый порт и приватность отчёта. Нативный `bundle_smoke.py` проверяет HTTPS и повторный запуск с сертификатом внутри готового пакета без внешнего Python/Node. Доверие в этих тестах задаётся только тестовому TLS-клиенту и не устанавливается в ОС. Это не подтверждает установку панели в настоящем Word.

`tests/test_word_install.py` проверяет согласие, повтор, отмену, частичную ошибку, сохранение чужих объектов и учебный DOCX. `web/tests/word-connection.test.js` проверяет Office.js протокол с явно имитированным Word. В CI `verify_word_setup_native.py` выполняет настоящую регистрацию и доверие в изолированных профилях Windows/macOS; Word в нём имитирован. Windows/Mac CI используют административный домен доверия на одноразовом runner, а пользовательское подтверждение остаётся отдельным сценарием. Такой результат подтверждает нативные операции, но не запуск Office.js и создание сноски в настоящем Word.

На Mac удаление подключения отключает SSL-доверие к собственному сертификату; запись сертификата и ключ сохраняются для повторного подключения. Общие правила безопасности системы не меняются.
# Библиотеки материалов (0.5.0)

Контракт: `libraries/<library_id>/library.json`, schema 1, ID/имя/ревизия, карточки и упорядоченные ID версий, результаты идемпотентных операций. `versions/<version_id>.json` — неизменяемые ID библиотеки/материала/версии/родителя, UTC-дата и комментарий, реквизиты, роли `original`/`translation`/`ready`, SHA-256/размер/страницы и эффективный рецепт подготовки. `blobs/<sha256>.pdf` хранит части по содержимому. Черновик перевода остаётся в исходной подаче; подтверждение привязано к хешам оригинала/перевода и выборок.

Публикуется только итоговый `library.json` после проверки всех файлов. Блокировка записи и ожидаемая ревизия защищают два окна; повтор токена возвращает записанный результат. Незавершённые операции хранятся в `.library-work`, не появляются в каталоге. Каталог читает метаданные порциями, без открытия PDF; файловые манифесты — источник истины.

Подача с библиотечным материалом использует schema 2; `provenance` содержит точные ID, хеш манифеста версии и базовый снимок переносимых полей. Импорт всегда копирует собственные файлы, не создаёт файловых ссылок. Schema 1 читается и восстанавливается без записи; перед первым импортом `schema.upgrade(..., target=2, persist=False)` создаёт и проверяет архив, а метаданные схемы и новый документ публикуются одной записью проекта. Старое приложение отклоняет schema 2. Проверки валидных/повреждённых примеров, отказа записи, отмены, повторов и независимого экспорта — `tests/test_library.py`.
