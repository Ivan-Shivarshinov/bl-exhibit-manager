# Проверка переходов в перечне 0.6.0

Остаётся подтвердить именно нажатие относительных ссылок в настольных программах. Автоматически уже проверяются точные цели, байты файлов, перенос папки и восстановление архива; рендер Word/LibreOffice проверяется отдельно. Установка панели Word для этого сценария не нужна.

На этом ПК доступны Microsoft Word 16.0.17928.20148 и SumatraPDF 3.5.2. Ниже — шаги для самостоятельной проверки.

Искусственные файлы находятся в `output/submission-index-qa/viewer-case/Moved Submission/`. Они не содержат рабочих материалов. Внутри — `Exhibit index.docx`, `Exhibit index.pdf` и два PDF в подпапке со сложным именем.

1. Откройте `Exhibit index.docx` в Word. Нажмите Ctrl и щёлкните «Тестовый переход 12». Ожидается открытие `Annex 12%.pdf`; на странице видна строка `Annex 12`.
2. Вернитесь к перечню и так же нажмите «Тестовый переход 13». Ожидается `Annex 13%.pdf` со строкой `Annex 13`.
3. Откройте `Exhibit index.pdf` в SumatraPDF и нажмите те же два названия. Ожидаются те же соответствующие PDF; соседняя ссылка не должна вести к предыдущему приложению.
4. Скопируйте **всю** папку `Moved Submission` в другое место, сохранив подпапки. Повторите переходы из перенесённых DOCX/PDF. Ожидается тот же результат без запуска BL Exhibit Manager.

Достаточно сообщить, какие из четырёх шагов прошли и какая программа использовалась. Если переход не сработал, нужны имя открытого перечня, выбранная строка и текст сообщения программы. Изменение настроек безопасности не входит в проверку.

До подтверждения этих переходов задача 3.5 и окончательное архивирование изменения не отмечаются завершёнными.
