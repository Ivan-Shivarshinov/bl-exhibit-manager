Состояние выпуска сверено 9 ноября 2026; цель развития уточнена пользователем 12 ноября. BL Exhibit Manager — публичный Open Source проект, лицензия Apache-2.0. Цель 1.0 — командная платформа работы с материалами дела: подготовка подач, поиск/OCR, переводы/версии, проверка, слушания, совместная работа, права, синхронизация и сервер. Самостоятельный локальный режим сохраняется. Полный паритет со всеми функциями коммерческих аналогов не установлен.

## Пользовательские пути

1. **Подготовить приложения:** добавить PDF → при необходимости выбрать фрагменты/перевести → оформить → проверить → получить комплект. Основной DOCX не обязателен.
2. **Собрать подачу из готовых материалов:** добавить готовые PDF и существующий DOCX → сопоставить сноски → разложить документы по папкам → получить DOCX/PDF и приложения. Панель Word, её сертификат и переводчик не нужны.
3. **Писать документ с помощью панели Word:** по желанию подключить надстройку → вставлять сноски и обновлять названия → передать DOCX в тот же основной процесс. Всегда можно использовать обычную загрузку файла.

Панель — **опциональное удобство**, не новый обязательный этап. Установленный конвертер для получения основного PDF — отдельное требование; он не означает обязательную установку надстройки.

Повторная сверка 23 сентября уточнила принятые сценарии штампов, пропусков, нумерации, состава комплекта, перевода и оглавления. DeepL, коммерческий API и файлообменник обсуждались как примеры/альтернативы, не обязательные интеграции. Многопользовательская работа не входила в MVP и 0.5.0; теперь она прямо включена пользователем в цель 1.0. Автоматическая передача данных и применение новых версий к подачам не разрешаются этим автоматически.

| **1.0** | Установка, обновление и эксплуатация платформы | Установщик/перенос/update/откат, политики резервов/администрирование, production Word |

Серверная модель предшествует совместным обсуждениям, чтобы не переписывать отдельную локальную систему проверки. Приём папок связан с OCR/поиском, сравнение содержания — с решением проверяющего. Дополнительные форматы готовы до слушаний. Общий центр операций/места приходит в 0.11; в 1.0 его не создают повторно.

[Полный план](RELEASE-PLAN-TO-1.0.md) фиксирует существующую основу, прирост, порядок/первый законченный срез, ошибки/приёмку и решения design для каждого выпуска. Нынешние данные вне приложения, preview/атомарные массовые действия, иерархия оформления, обновление ссылок Word, resume одиночного перевода, перестановка страниц, архивы и история используются. Регрессия не считается новой функцией. Безопасность/ресурсы/перенос добавляются с каждой новой сущностью, а не откладываются на 1.0.

## Что принято, что ещё предлагается

Цель командной 1.0 и пересобранная карта выпусков приняты пользователем. 0.7.0 реализуется по [активному OpenSpec](../openspec/changes/submission-pdf-volumes/proposal.md); выпуск ещё не опубликован. Семантика/AI, дополнительные форматы, межпроектные дубли и расширенные PDF-действия сохранены в ней как явно отмеченные предложения, а не прежние утверждённые требования. Старое «не входит в 0.5» не исключает направление из будущего. Ни один пункт не снимается без записи решения пользователя.

Платный хостинг, способ входа/развёртывания, внешние модели/передачи данных, подпись приложений и production-канал Word требуют конкретных решений до реализации соответствующего этапа. Marketplace не выбран автоматически. Общая синхронизация не отменяет явное принятие версии в отдельную подачу. Собственный совместный редактор текста Word и полный паритет с неизвестными функциями аналогов не обещаются неявно; решения A01–A08 сохранены в сверке.

## Что считать готовностью 1.0

- Все принятые строки сверки завершены и связаны с требованиями/доказательствами; нет самовольного сокращения или закрытия только наличием кода.
- Один материал используется в двух подачах с разными номерами/обозначениями; новая версия применяется только к выбранной. Оригиналы, правки и старые ZIP/снимки сохраняются.
- Автономный локальный режим и перенос без сервера/библиотеки/Word остаются доступны.
- Команда реально работает в пределах прав, разрешает конфликты/обрыв сети; закрытые данные не утекают через поиск/показ/выдачу/AI.
- Клиенты Windows/Mac и сервер устанавливаются, обновляются и восстанавливаются по проверенной инструкции. Пределы нагрузки/совместимости измерены; неподтверждённое названо явно.
- Автоматические, UI/реальные прикладные проверки и выпуск разделены. Нативные пакеты/суммы, серверная поставка и инструкции соответствуют проверенному коду.
- OpenSpec валиден; завершённое синхронизировано и архивировано. Публикация/объединение выполняются отдельно по указанию пользователя.
