# Проверка панели Word и новых редакций

Тестируйте на учебных документах. Эта инструкция относится к ветке разработки 0.2.0-dev.1, а не к релизам 0.1.x.

Панель опциональна. Для обычной загрузки готового DOCX/PDF эту настройку выполнять не нужно. Актуальные незакрытые задачи — [OpenSpec](../openspec/changes/optional-word-authoring/tasks.md).

## Перед началом

Нужен Word с WordApi 1.5: Microsoft 365 Windows 2302 (сборка 16130) или новее; Mac 16.70 или новее. Локально основные кнопки проверены на Microsoft 365 Windows 16.0.17928.20148. Для Mac живая проверка панели пока остаётся открытой.

Настройка локального сертификата и надстройки описана в [WORD-SETUP.txt](../exhibit/assets/WORD-SETUP.txt). Если установка сертификата зависает или появляется запрос доверия, этот шаг выполняет пользователь. Не публикуйте файлы сертификатов с закрытым ключом.

## 1. Создание сноски

1. Запустите приложение и откройте учебную подачу. В Word создайте отдельный документ с несколькими предложениями.
2. Откройте панель BL Exhibit Manager и выберите ту же подачу.
3. Поставьте курсор после первого предложения. В панели выберите RLA-31, в поле страницы/параграфа напишите `paras. 5–6`, нажмите «Создать сноску в Word».
4. Внизу должна появиться настоящая сноска. Ссылка чёрная и без подчёркивания; жирным выделено только обозначение приложения (`RLA-31`), остальное название — обычным; `paras. 5–6` — обычный текст за пределами ссылки.
5. Поставьте курсор в эту сноску. Выберите другое приложение и нажмите «Добавить в существующую сноску». Должны получиться две отдельные ссылки, разделённые точкой с запятой.
6. Сохраните DOCX, закройте и откройте его снова. Панель должна найти обе ссылки кнопкой «Проверить ссылки».

## 2. Обновление названия и номера

1. В основном приложении измените название и номер первого приложения.
2. В панели Word нажмите «Проверить ссылки». Должны быть показаны старый и новый тексты.
3. Примените выбранное изменение. Указание `paras. 5–6` и соседняя ссылка должны остаться прежними.
4. Измените текст одной ссылки вручную в Word. Повторная проверка должна отметить ручную правку и не перезаписать её автоматически. Чтобы вернуться к автоматически обновляемой ссылке, восстановите прежний текст или вставьте ссылку заново через панель.
5. После предварительной проверки измените документ ещё раз. Применение старого плана должно потребовать повторной проверки.

## 3. Передача и сборка

1. Сохраните Word. В панели нажмите «Передать DOCX в приложение».
2. Откройте выбранную подачу в основном приложении и обновите страницу. Сопоставьте и подтвердите сноски, подтвердите приложения, соберите ZIP.
3. Распакуйте всю папку Submission. Проверьте ссылки в Word и PDF, затем переместите всю папку и повторите переходы. Для готовых файлов панель не нужна.
4. Создайте ещё одну редакцию DOCX, добавив предложение и переставив сноску. Передайте её в приложение: однозначные прежние связи должны сохраниться, изменённые места — отображаться для проверки.

## 4. История

1. Соберите первый ZIP. Измените приложение, подтвердите результат и соберите второй.
2. В «Проверка и экспорт» откройте «История комплектов». Должны быть две версии и список изменений.
3. Скачайте первую версию — она должна содержать прежние документы. Эта последовательность уже проверена автоматически и в браузере.

Живые тесты 1–3 нужны на Windows и Mac. Они включают ограничения Office.js, которые нельзя подтвердить обычными тестами Python или браузером без Word.

## Результат проверки 21 сентября 2026

На Windows через настоящий Office.js прошли создание сноски с `paras. 5–6`, добавление второй ссылки, обновление первого номера и названия без изменения соседней ссылки или параграфа, отказ применять устаревший план после ручной правки, сохранение/закрытие/открытие и повторное обнаружение обеих ссылок. DOCX передан кнопкой панели; ZIP получен через локальный API и настоящий конвертер Word, цели в DOCX/PDF проверены по содержимому файлов. Переходы после переноса этого нового комплекта кликами не проверялись.

Эти выполненные проверки Windows повторять вручную без изменений кода не требуется. Перед выпуском остаются короткое название через кнопку, включённая запись исправлений, ручная правка начертания, интеграция серверного оформления из rc.5 и проверка пакета; на Mac выполнить разделы 1–3. Состояние всей ветки — в [плане](WORD-WORKFLOW-PLAN.md).

## Приёмка объединённой ветки 23 сентября 2026

Автоматические проверки и обмен XML с настоящим Word подтвердили новое сохранение начертания. Для обновлённой кнопки остаются следующие действия на учебном документе:

1. Задайте короткое название приложения, вставьте через панель короткую ссылку и `para. 2`. Короткое название должно быть ссылкой, параграф — отдельным текстом.
2. Сделайте весь текст названия после обозначения курсивным. Измените номер/название приложения, проверьте ссылки в панели и примените обновление. Обозначение остаётся жирным, название курсивным, соседняя ссылка и параграф прежними.
3. Сделайте курсивным только одно слово внутри названия и снова измените название приложения. Применение должно объяснить смешанное оформление и не менять выбранные ссылки. Обновите такую ссылку вручную.
4. Включите «Рецензирование → Исправления» и попробуйте вставку/обновление. Панель должна попросить отключить запись, не изменяя документ. После отключения повторите операцию.
5. Передайте DOCX, подтвердите сопоставление, соберите комплект и переместите всю распакованную папку. Проверьте переходы в Word/PDF. На Mac дополнительно пройти первоначальное подключение и вставку второй ссылки по разделам выше.

Полный путь новой редакции и двух ZIP через HTTP с настоящим Word проверен скриптом `verify_revisions_office.py`; повторять его вручную на Windows без новой причины не требуется. Средство управления окнами в текущем проходе недоступно, поэтому тесты документов через COM не объявляются проверкой кнопок Office.js.
