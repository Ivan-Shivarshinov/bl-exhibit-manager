# Сохранение и восстановление проекта

Нажмите **«Архив проекта»** рядом со списком проектов.

1. **Сохранить проект** — скачать ZIP со всей сохранённой работой. Дождитесь окончания скачивания и сохраните файл в надёжном месте.
2. На этом или другом компьютере откройте **«Архив проекта» → «Восстановить проект»** и выберите ZIP.
3. Приложение проверит архив и покажет его состав. Нажмите **«Восстановить»**. Если проект уже существует, доступно **«Восстановить копию»**; существующий проект не перезаписывается.

Архив содержит исходные PDF/DOCX, ранее загруженные редакции, настройки, сопоставления ссылок, сохранённые переводы и историю готовых комплектов. Незавершённая работа остаётся незавершённой. Активный перевод перед сохранением нужно завершить или остановить в переводчике. Несохранённые изменения в Word или полях интерфейса сначала сохраните.

Архив проекта отличается от ZIP подачи: он нужен для продолжения работы в приложении. Для отправки готовых документов используйте **«Проверка и экспорт»**.

Перенос работает между Windows и macOS. Вход в Claude/Codex, сертификат панели Word и настройки компьютера не переносятся. Для восстановления они не нужны; конвертер потребуется при следующей подготовке основного PDF. При восстановлении копии выберите её в панели Word и проверьте ссылки перед обновлением. Исходный DOCX и прежние ZIP не переписываются.

Ограничения: до 8 ГБ распакованных данных, 20 000 файлов; отдельный файл настроек — до 20 МБ. При повреждении, неизвестной версии формата или нехватке места восстановление прекращается; существующие проекты сохраняются. Повторите операцию после устранения причины. Произвольно редактировать содержимое архива не следует.

## Формат для разработчиков

Версия архива — `1`, схема проекта пока `1`. Манифест `backup.json` содержит тип `exhibit-manager-project`, дату, размер и SHA-256 каждого файла. Проверяются все записи, связи с исходниками и пары истории. Запрещены ссылки файловой системы, дубли, неизвестные категории, пути вне проекта. Имена внутренних файлов ASCII, не длиннее 200 символов; нормализация NFC/casefold учитывает Windows и macOS.

Состав: `project.json`, все `inputs/<sha256>.pdf|docx`, `translation-<id>.json`, `translation-source-<id>.json`, завершённые `exports/<id>/manifest.json` и `Submission.zip`. Подтверждённые PDF перевода находятся в inputs. Не включаются `main-pdf` (воспроизводимый кэш), временные записи и незавершённые `.pending-*` истории. Неизвестный файл внутри проекта вызывает отказ, а не молчаливую потерю данных. Корень пользовательских данных не архивируется.

Снимок создаётся под существующей блокировкой записи Store, передача готового ZIP — без неё. Восстановление потоковое, во временный каталог рядом с проектами, с атомарным переименованием после проверок. Временная загрузка удаляется при завершении или отмене; оставшиеся после закрытия браузера/сбоя каталоги удаляются через 24 часа при следующей операции с архивами.

Копия получает новый ID проекта, сохраняя ID документов. Привязки Word ограничены хешем исходного DOCX и точными известными маркерами. В новой редакции наследуются только эти же маркеры. Панель после явного выбора копии предлагает обновить адреса на её ID; глобальных псевдонимов нет.

Преобразования схемы — последовательные функции в `schema.UPGRADES`. Схема 1 открывается без записи. Перед будущим преобразованием создаётся и проверяется архив `backups/before-upgrade-*.zip` в папке данных; путь сохраняется в `schema_backup`. Меняется только metadata, исходники и история остаются прежними. Несуществующие старые форматы намеренно не придуманы: механизм проверяется искусственным преобразованием 1→2.
