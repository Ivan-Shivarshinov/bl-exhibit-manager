# Перечень приложений — разработка 0.6.0

Перечень необязателен. Он содержит все PDF-приложения выдаваемого комплекта; основной документ в него не входит. Настройки относятся к подаче, а не к библиотечному материалу.

## Как пользоваться

1. Подготовьте приложения или загрузите готовые PDF. Основной Word-документ необязателен.
2. Откройте «Проверка и экспорт» и отметьте «Добавить перечень приложений».
3. Выберите заголовок, язык подписей, DOCX/PDF, дополнительные колонки и порядок. Нажмите «Сохранить перечень».
4. Нажмите «Обновить перечень». Проверьте все названия, пути и фактические страницы в таблице; названия документов не переводятся автоматически.
5. Нажмите «Собрать подачу · ZIP». В корне `Submission` появятся выбранные `Exhibit index.docx` и `Exhibit index.pdf`.
6. Распакуйте весь ZIP и переносите `Submission` целиком, сохраняя вложенные папки. Откройте перечень из распакованной папки.

После правок приложение просит обновить перечень. Если его имя конфликтует с приложением/папкой, измените путь документа в «Документы» или «Папки Submission»; переименования без вашего решения не будет. При ошибке исправьте причину и повторите «Обновить перечень»; прежние ZIP остаются в истории. Выключенный перечень сохраняет прежний путь сборки.

## Оформление и ссылки

Перечень использует A4, таблицу с повторяемой шапкой, кириллицу/латиницу DejaVu Sans и отдельные номера своих страниц. DOCX редактируется в Word/LibreOffice; PDF создаётся напрямую без Office. Два формата содержат одинаковые значения, но их разбивка на страницы может различаться. Очень большая строка или отсутствующий в шрифте символ вызывают явный отказ вместо потери текста.

Ссылкой служит название приложения. DOCX хранит относительные внешние гиперссылки, PDF — относительные GoToR-переходы. Программы могут запрашивать разрешение открыть соседний файл. Встроенный просмотр внутри ZIP/браузера может не поддерживать такие переходы; используйте распакованный комплект и подходящий настольный просмотрщик. Проверка структуры ссылок и реальное нажатие в конкретной программе — разные результаты; их версии и состояние фиксируются в отчёте приёмки.

Генерация перечня не требует панели, сертификатов и переводчика, не меняет приложения с формами/подписями и не создаёт единый PDF-том. Для основного DOCX по-прежнему нужен отдельный конвертер.

## Настройки и сохранность

Первое сохранение настройки перечня переводит проект в формат 3. Перед этим приложение сохраняет и проверяет архив прежнего состояния; путь находится в `schema_backup` и показывается в приложении. Открытие проекта и чтение настройки не меняют формат. Отключение перечня оставляет формат 3.

Для возврата к приложению 0.5.1 используйте архив `backups/before-upgrade-<id>-<token>.zip`, созданный **до** изменения формата: запустите прежнее приложение и выберите «Восстановить проект». При совпадении проекта выберите независимую копию. Не заменяйте вручную `project.json` и не пытайтесь открыть формат 3 старым приложением. Новые изменения после перехода не входят в прежний архив.

Архив проекта формата 3 включает настройку перечня, исходники, переводы, решения и историю ZIP. Восстановление не требует доступной библиотеки; импорт/обновление материалов не меняют настройку перечня.

## Контракт разработчика

`submission_index` существует только в schema 3 и содержит ровно следующие поля:

| Поле | Значения |
|---|---|
| enabled | bool; по умолчанию false |
| language | ru / en; меняет служебные подписи |
| title | 1–200 символов без управляющих знаков |
| formats | уникальные docx / pdf; при включении минимум один |
| columns | уникальные pages / path; обозначение и название обязательны |
| order | identifier / project / folder |

Начальные значения: русский заголовок, оба формата, колонка страниц, порядок по обозначению. Клиент меняет стандартный заголовок вместе с языком, пока пользователь не задал собственный. Сервер сохраняет явно переданный заголовок без перевода.

Переход 1→2→3 / 2→3 использует проверенный архив исходной схемы и атомарную запись метаданных. Настройка проверяется до резервного копирования. Отказ копирования, проверки или записи не меняет сохранённый проект. Архиватор строго проверяет настройку при сохранении и восстановлении. Схема библиотеки остаётся 1; библиотечный импорт использует `max(2, project.schema)` и не понижает формат.

`GET/PATCH /api/projects/{pid}/submission-index` читает/сохраняет конфигурацию; `POST .../preview` возвращает все строки и `preview_token`; `GET .../status` позволяет проверить актуальность в другом окне. При включении экспорт принимает `preview_token`; он не заменяет валидацию источников, оформления и основного документа.

Снимок готовит PDF вне глобальной блокировки и считает страницы по окончательным байтам. Перед публикацией перечня и истории повторно проверяются проект и отпечаток. Для одного проекта допустима одна операция; кеш подготовленных PDF ограничен 8 ГБ и доступным местом, живёт во временной папке до замены/вытеснения/завершения процесса. Ошибка и прерывание подготовки удаляют её незавершённый каталог; повреждённый кеш восстанавливается обычным обновлением. Полная копия проекта не создаётся. Настройка заголовка/колонок/порядка не меняет ключ подготовки приложений или основного PDF.

Каждый выбранный перечень сохраняется в манифесте истории как `kind: submission_index`, с путём и SHA-256; `changes.index_changed` отдельно показывает изменение перечня. Старые манифесты читаются без новых полей; старые ZIP не переписываются.
