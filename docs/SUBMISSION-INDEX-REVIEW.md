## Блокирующие замечания реальной проверки Windows

Среда: Microsoft Word **16.0.17928.20148**, SumatraPDF **3.5.2**. Версии считаны из установленных исполняемых файлов. Переход Word выполнен через контекстное меню «Открыть гиперссылку»; PDF — нажатием текста ссылки.

1. **DOCX: ссылка в папку с кириллицей не открывается.** В контрольном перечне ссылка `Материалы/Annex 13.pdf` вызывает «Не удается открыть указанный файл». Обычная `Annex 12.pdf` из того же DOCX успешно открывается в SumatraPDF после штатного подтверждения Word. Из PDF-перечня ссылка в эту русскую папку работает. Значит, файл существует и открытие PDF на компьютере настроено. Генератор DOCX записывает кириллицу как последовательности `%D0...` в `word/_rels/document.xml.rels`; это наблюдение о реализации, а не доказанная окончательная причина отказа Word.
2. **PDF: `#` в папке обрезает путь при переходе.** Ссылка `Hash #/Annex 13.pdf` в SumatraPDF сообщает, что `.../Hash` не найден. Сложный путь исходного примера `Материалы # 50%/O'Brien & Co/Annex 12%.pdf` аналогично обрезается до `.../Материалы`. Контроли с пробелом, кириллицей и `%` без `#` успешно открываются. В PDF записан относительный GoToR с исходным `/F` и `/UF`; принадлежность причины генератору или совместимости просмотрщика ещё требует проверки. Заявленное поведение в этой среде не достигнуто.

| Контрольный путь | Word DOCX | SumatraPDF, прямой PDF-перечень |
|---|---|---|
| `Annex 12.pdf` | Открыт правильный файл | Открыт правильный файл |
| `Материалы/Annex 13.pdf` | Ошибка открытия | Открыт правильный файл |
| `Percent 50%/Annex 12%.pdf` | Отдельно не проверялся | Открыт правильный файл |
| `Hash #/Annex 13.pdf` | Отдельно не проверялся | Путь обрезан, файл не открыт |
| Сложный путь исходного примера с кириллицей, `#`, `%`, апострофом и амперсандом | Ошибка открытия | Путь обрезан, файл не открыт |

Контрольные DOCX/PDF заново созданы действующими `exhibit.index_documents.docx` и `pdf_document`, без изменения кода и без ручной правки ссылок. Все цели существуют рядом с перечнем. В четырёх контрольных PDF намеренно одинаковое искусственное содержимое; успешный переход различается по открытому имени файла, а не по заголовку внутри страницы. Исходный двухстрочный пример имеет разные документы Annex 12/13.

Для повторения: открыть `output/review-v060-20261029/viewer-controls/Controls.docx` и `Controls.pdf`; нажать строки PLAIN, CYRILLIC, PERCENT, HASH. Исходный сложный пример находится в `output/submission-index-qa/viewer-case/Moved Submission/`. Проверка обеих соседних целей до/после нового переноса не завершена из-за обнаруженных отказов; её нельзя отмечать успешной.

Перед приёмкой: исправить или доказательно разрешить совместимость относительных ссылок, сохранить исходные имена/файлы без скрытого переименования, добавить адресные регрессии и повторить переходы на конечных пакетах. Автоматическая проверка декодированного пути и наличия файла не заменяет открытие через Word/PDF-программу. Не менять системную безопасность ради прохождения проверки.
