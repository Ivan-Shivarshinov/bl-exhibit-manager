Окончательный код: 328 Python и 25 JS проходят на Windows/Mac Intel/Mac ARM; строгая валидация OpenSpec — 13/13. Интерфейс собирается. Внешний браузерный плагин недоступен, поэтому используется настоящий Chromium через Playwright на изолированном сервере. Локально повторены адресные регрессии новых изменений; реальные нажатия в настольных программах не подменяются этими результатами.

Нагрузка исходного приложения: 100 готовых PDF → предпросмотр/ZIP — 1,54 с; 500 строк → подготовка, DOCX/PDF и повторный предпросмотр — 10,27 с. `tracemalloc` зафиксировал 14,64 МБ выделений Python (это не вся память процесса); временные PDF — 12,66 МБ. Все 500 строк/целей присутствуют, 500 вызовов подготовки вместо повторной конвертации; временная папка после закрытия отсутствует. Финальные значения могут уточняться в нативных отчётах.

Состав проверен: нет проектов, исходников пользователей, истории обработки, диагностических журналов или служебного PEM среды Codex. Описание 0.6.0 с локальными ссылками — `RELEASE-NOTES.md` рядом с пакетами; при публикации ссылки заменяются ссылками на загруженные assets, публикация сейчас не выполнялась.

Локальные доказательства вне Git: `output/submission-index-qa/` — отчёты HTTP/UI/нагрузки, синтетические ZIP и изображения; `office/` — настоящий Word. Скрипты в Git генерируют эти материалы заново. Частные документы коллег не используются.

Первая нативная попытка CI [40861319514](https://github.com/Ivan-Shivarshinov/bl-exhibit-manager/actions/runs/40861319514) прошла 325 Python/25 JS и новый браузерный/нагрузочный сценарий на трёх платформах. Все пакеты создали перечень и ZIP, но проверка переноса использовала нераскрытый системный путь временной папки. Исправлено сравнение с каноническим корнем (на Mac `/var` может разрешаться в `/private/var`, на Windows короткое имя профиля — в полное). Это исправление проверки, не основание объявить весь CI успешным. Последующие задания обмена не получили невыданные пакеты; их отказ не скрывается повторным запуском.

Локальный сбой готовности Windows: внешний клиент видел работающий сервер, а `urlopen` внутри замороженного запускателя возвращал `FileNotFoundError`. Для собственного HTTP на `127.0.0.1` запускатель теперь использует прямое HTTP-соединение, без настройки HTTPS/прокси. Регрессия использует настоящий локальный HTTP-сервер, недоступный прокси и отказ создания постороннего HTTPS-контекста. Сам сервер не менял адрес/доступ. Реальный локальный пакет прошёл 0.5.1→0.6.0→отказ старого приложения открыть schema 3 без записи→восстановление архива schema 1 в 0.5.1 (`upgrade-report.json`).

Дальнейшая проверка TLS установила причину именно локальной сборки: встроенный Python Codex добавляет в `SSLContext.__new__` загрузку служебного PEM рядом со стандартной библиотекой; после заморозки файл отсутствует. Такой дистрибутив не подходит для выдачи, даже если PDF-сценарий проходит. Упаковщик теперь отвергает эту среду до сборки; финальные пакеты создаются стандартным CPython в нативном CI. Служебные сертификаты не копируются, проверка TLS не ослабляется. Этот отказ среды не приписывается нативным CI-пакетам.

Пользователь запретил управление своим ПК. До остановки был только открыт Word; нажатия/переходы не подтверждены. Дальнейшая работа ограничена кодом, изолированными автоматическими проверками и нативным CI; открытие окон и управление мышью/клавиатурой не выполняются.

Остались реальные нажатия новых ссылок в настольных программах и последующее архивирование change. [Точные шаги](SUBMISSION-INDEX-MANUAL-CHECK.md) используют два искусственных приложения; общая приёмка Word-панели не повторяется. До подтверждения задача 3.5 остаётся открытой. Код, конечные пакеты и все автоматические проверки готовы; PR не объединён, публикация выполняется отдельно по указанию пользователя.

Вторая попытка [40864803732](https://github.com/Ivan-Shivarshinov/bl-exhibit-manager/actions/runs/40864803732): готовый Windows-пакет полностью прошёл проверку; нативные пакеты на обоих Mac прошли состав/ZIP/UI/нагрузку и обновление с 0.5.1. Отдельный скрипт LibreOffice ожидал выходной basename, не совпадающий с входным; исправлено размещением копии в собственном каталоге, напрямую созданный PDF теперь дополнительно проверяется по SHA-256 на неизменность. В заданиях обмена все входные архивы восстановились с точными исходниками/историей, затем тест сравнивал ID чужого документа с ID новой местной фикстуры. Исправлено сравнением с сохранённым предпросмотром **того же входного архива** (`index-model.json`), без ослабления проверки ID/значений/страниц.

Тот же официальный Windows-пакет дополнительно запущен локально в изолированном профиле, с пустым PATH для Python/Node и без окна браузера: 100 PDF, два перечня/ZIP, перенос, старая история и независимое восстановление — 15,00 с; хеши исходников сохранены. Отдельная регрессия библиотеки проверяет смену перевода 1→2 страницы и возврат: в выбранной подаче перечень меняется 2→3→2, все страницы сохраняют Annex 12, другая подача и прежние ZIP побайтово прежние.

Финальная проверка синхронизации воспроизвела возможность записи проекта между последней проверкой и помещением предпросмотра в кеш. Проверка актуальности и публикация теперь находятся в одной секции блокировки; подготовка PDF остаётся снаружи. Управляемый тест с двумя потоками сначала падал, после исправления проходят все 24 адресных регрессии перечня. Окончательная матрица включает эту правку. Одновременные push/PR для одной ветки объединены в одну группу CI, чтобы не выполнять два одинаковых набора нативных сборок.
