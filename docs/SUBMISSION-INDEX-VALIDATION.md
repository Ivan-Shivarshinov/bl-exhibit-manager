Локально: 325 Python и 25 JS проходят; строгая валидация OpenSpec — 13/13. Новый код интерфейса собирается. Внешний браузерный плагин недоступен, поэтому используется настоящий Chromium через Playwright на изолированном сервере. Последующие изменения повторяются адресными проверками и полным CI.

Нагрузка исходного приложения: 100 готовых PDF → предпросмотр/ZIP — 1,54 с; 500 строк → подготовка, DOCX/PDF и повторный предпросмотр — 10,27 с. `tracemalloc` зафиксировал 14,64 МБ выделений Python (это не вся память процесса); временные PDF — 12,66 МБ. Все 500 строк/целей присутствуют, 500 вызовов подготовки вместо повторной конвертации; временная папка после закрытия отсутствует. Финальные значения могут уточняться в нативных отчётах.

Локальные доказательства вне Git: `output/submission-index-qa/` — отчёты HTTP/UI/нагрузки, синтетические ZIP и изображения; `office/` — настоящий Word. Скрипты в Git генерируют эти материалы заново. Частные документы коллег не используются.

Первая нативная попытка CI [40861319514](https://github.com/Ivan-Shivarshinov/bl-exhibit-manager/actions/runs/40861319514) прошла 325 Python/25 JS и новый браузерный/нагрузочный сценарий на трёх платформах. Все пакеты создали перечень и ZIP, но проверка переноса использовала нераскрытый системный путь временной папки. Исправлено сравнение с каноническим корнем (на Mac `/var` может разрешаться в `/private/var`, на Windows короткое имя профиля — в полное). Это исправление проверки, не основание объявить весь CI успешным. Последующие задания обмена не получили невыданные пакеты; их отказ не скрывается повторным запуском.

Локальный сбой готовности Windows: внешний клиент видел работающий сервер, а `urlopen` внутри замороженного запускателя возвращал `FileNotFoundError`. Для собственного HTTP на `127.0.0.1` запускатель теперь использует прямое HTTP-соединение, без настройки HTTPS/прокси. Регрессия использует настоящий локальный HTTP-сервер, недоступный прокси и отказ создания постороннего HTTPS-контекста. Сам сервер не менял адрес/доступ. Реальный локальный пакет прошёл 0.5.1→0.6.0→отказ старого приложения открыть schema 3 без записи→восстановление архива schema 1 в 0.5.1 (`upgrade-report.json`).

Пользователь запретил управление своим ПК. До остановки был только открыт Word; нажатия/переходы не подтверждены. Дальнейшая работа ограничена кодом, изолированными автоматическими проверками и нативным CI; открытие окон и управление мышью/клавиатурой не выполняются.

Оставшиеся условия выпуска: итоговые пакеты Windows/Mac Intel/Mac ARM, взаимный перенос архивов и окончательная сверка. Реальные переходы в настольных программах остаются отдельной непроведённой проверкой. Публикация выполняется отдельно по указанию пользователя.
